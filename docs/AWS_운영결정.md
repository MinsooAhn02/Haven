# AWS 운영 결정 (2026-11-09)

**상태:** 조장 추천안 — 보람·민성 확인 대기. 이의 없으면 확정하고, 확정 시 이 줄과 아래 "상태" 칸을 바꾼다.
**결정:** 안민수(조장) · **확인:** 김보람(IAM·비용), 이민성(네트워크·서버)
**근거:** [보람 결정현황](../김보람/민수_인계_결정현황.md), [민성 네트워크 설계](../이민성/network/설계.md) 5·6장, 요찬 앱 계약(`Yochan` 브랜치 `신요찬/앱계약.md`). 가격은 민성 설계의 2026-11-06 확인값이며 새로 조회하지 않았다.

이 문서는 **어떻게 운영할지**에 대한 결정이다. 실제 AWS 자원 생성·IAM 적용은 각 담당이 확정 후 따로 진행한다.

## 예산 경보와 행동

경보는 알림일 뿐 결제를 막지 않는다. 금액마다 누가 무엇을 할지 미리 정한다.

| 사용액 | 행동 | 담당 |
|---|---|---|
| $50 | 사용 추세와 남은 일수 공유 | 보람 |
| $80 | 다른 계정 이전 준비 시작(새 계정 접근·IAM 준비, 최신 백업 확보) | 보람·민수 |
| $95 | NAT·ALB 삭제, 새 계정에서 재구성 | 민성(네트워크)·민수(서버) |

보람 비용표에 **"$100으로 며칠 운영 가능한지"**를 꼭 넣는다. NAT만으로 하루 약 $1.5이고, EC2·ALB·데이터 비용이 더해진다.

## 계정 이전 대비 (9번)

콘솔에서 손으로 만들고 끝내지 않는다. 다른 사람이 새 계정에서 같은 결과를 낼 수 있어야 한다.

| 담당 | 남길 것 |
|---|---|
| 민성 | 구축 절차서(순서·값, 가능하면 AWS CLI 명령). 계정 ID·ARN·자원 ID를 직접 쓰지 않고 변수로 |
| 보람 | IAM 정책·Role JSON에서 계정 ID를 변수로. 새 계정 접근·MFA·예산 경보 설정 절차 |
| 민수 | 서버 설치·앱 배포 스크립트와 절차(`안민수/공통실행.md`) |
| 데이터 | DB dump + 첨부 + manifest 백업 → 새 계정에서 복원. **2회차 첫 배포 직후 한 번 연습**(원래 4회차 복원 계획을 앞당김) |
| 도메인·인증서 | 계정과 분리해 새 계정에 다시 연결할 수 있게(3회차) |

## 확인 요청

- **민성:** 5번 — Ubuntu 24.04 기본 Python 3.12, apt 저장소 80 포트가 맞는지. 서버 사양·대수·하루 가동 시간을 보람에게
- **보람:** 2번 — 위 사양 기준 "$100으로 며칠" 비용표. 확정되면 결정현황 문서에 승인/보류·결정자·날짜 반영
- 이견이 있는 항목만 짧게 통화로 정하고, 결과를 이 문서 "상태" 칸에 기록한다.

## 이번 결정으로 바뀌는 작업

- 민성: 구축 절차를 계정 이전 가능하게 작성, SG outbound 80 반영
- 보람: 비용표에 $100 기준 운영 일수, 경보 $50/$80/$95 설정 계획, IAM JSON 계정 ID 변수화
- 민수: 서버 설치를 스크립트화, 2회차 첫 배포 직후 백업·복원 연습
- 요찬: 앱이 Python 3.12에서도 동작하는지 계속 유지(CI가 3.12·3.13 둘 다 시험)
