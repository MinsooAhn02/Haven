# 서버 배포 인계 (`안민수/server/`)

원본 절차는 `안민수/공통실행.md`의 "서버 설치·배포", "DB 백업·복원", "수요일 첫 배포 절차"다. 여기에는 민성이 혼자 할 때 필요한 것만 다시 정리했다.

## 1. 스크립트

| 파일 | 어디서 | 하는 일 |
|---|---|---|
| `common.sh` | 모두 | 공통 함수(로그, 실패 시 멈춤). 다른 스크립트가 같은 폴더에서 읽음 |
| `put-secrets.sh` | 조장 PC/CloudShell | SSM `/haven/*` 비밀값 3개 생성. **이미 생성됨, 다시 실행할 일 없음** |
| `db-setup.sh` | db-1 | PostgreSQL 16, DB `haven`, `haven_owner`(migrate)·`haven_app`(CRUD만), web-1에서만 접속 |
| `web-setup.sh` | web-1 | venv·Gunicorn(systemd)·Nginx·첨부 폴더, deploy key 생성 후 공개키 출력. 여러 번 실행해도 결과가 같음 |
| `deploy.sh` | web-1 | `deploy.sh <40자리 commit>`: 받기 → 의존성 → migrate → 전환 → `/healthz`. 실패하면 이전 release로 복귀 (DB migration은 되돌리지 않음) |
| `backup.sh` / `restore.sh` | db-1 | DB 덤프 → `s3://haven-backup-777171525040/db-backups/<UTC시각>/`, 격리 DB `haven_restore_check`에 복원 후 행 수 비교 |
| `backup-uploads.sh` / `restore-uploads.sh` | web-1 | 첨부 파일 tar + sha256 목록 → DB 백업과 같은 `db-backups/<시각>/`에 한 묶음으로 (`haven` 서비스가 멈춰 있어야 실행됨), 복원은 격리 폴더 `/srv/haven/restore-check/uploads`에 풀고 비교 |
| `test-wsl.sh`, `test-backup-wsl.sh` | WSL Ubuntu-24.04 | 가짜 서버 시험. 스크립트를 고치면 다시 돌림 (46개 / 31개 통과 기록) |

## 2. 첫 배포 (11/11 수)

**필요한 것:** web-1 `i-0cca7ab298c2f67fd` (10.20.10.83), db-1 `i-05de66c16d7106764` (10.20.20.147), 민성 Session Manager 권한(IAM 14번, 오전에 확인), main 최신 40자리 commit (`git rev-parse origin/main`).

**스크립트를 서버에 넣는 법 (첫 설치 때만):** 서버는 아직 코드를 받을 수 없어서 붙여넣기로 넣는다.
1. 내 PC Git Bash에서 `sha256sum 안민수/server/common.sh 안민수/server/db-setup.sh` (web-1은 `web-setup.sh deploy.sh`까지)
2. Session Manager에서 `sudo -i` → `mkdir -p /root/setup && cd /root/setup`
3. `cat > common.sh <<'EOF'` → 파일 내용 붙여넣기 → `EOF`
4. 서버에서 `sha256sum *.sh` → 1번 값과 같아야 실행. 다르면 붙여넣기가 깨진 것이니 다시 넣는다.

| # | 어디서 | 할 일 | 성공 확인 |
|---|---|---|---|
| 1 | db-1 | `WEB_IP=10.20.10.83 bash db-setup.sh` | 마지막 줄 `OK  db-setup` |
| 2 | web-1 | `DB_HOST=10.20.20.147 ALLOWED_HOSTS=haven.local bash web-setup.sh` (ALB·도메인 생기기 전 임시 이름) | 마지막에 공개키 출력 |
| 3 | GitHub | Settings > Deploy keys에 2번 공개키 등록, **Allow write 끔** — **admin만 가능 → 민수가 등록** | |
| 4 | web-1 | `bash deploy.sh <40자리 commit>` | `OK  deployed`, `curl -s -H 'Host: haven.local' http://127.0.0.1/healthz` → ok |
| 5 | web-1·db-1 | 연결확인표: Web→DB 5432 성공, 다른 곳→DB 거부, postgres 원격 접속 거부 | 이민성 연결확인표에 결과 기록 |
| 6 | 둘 다 | `reboot` → 다시 접속 | healthz ok, `systemctl is-active haven nginx postgresql` 전부 active |
| 7 | 백업 연습 | web-1 `systemctl stop haven` → db-1 `backup.sh`(시각 출력됨) → web-1 `backup-uploads.sh <그 시각>` → web-1 `systemctl start haven` → db-1 `restore.sh <시각>` → web-1 `restore-uploads.sh <시각>` | 각 단계 `OK`, 행 수·파일 sha 일치 |

7번의 버킷 지정: `BACKUP_BUCKET=haven-backup-777171525040 bash backup.sh` (나머지도 같은 변수).

## 3. 두 번째 배포부터

코드와 같이 받은 스크립트를 쓴다. 붙여넣기는 필요 없다.

```bash
sudo -i
bash /srv/haven/current/안민수/server/deploy.sh <main 40자리 commit>
```

- 배포 전에 PR 병합 + CI 통과 확인, 배포한 commit을 운영기록에 남긴다.
- 배포는 **09~21시**에만 한다. 21시 `night.sh` 이후에는 NAT가 없어 pip·apt·SSM 비밀값 읽기가 안 된다.
- 다음 날 EC2가 다시 시작되면 haven·nginx·postgresql은 자동으로 뜬다 (6번 재부팅으로 확인할 것).

## 4. 도메인이 생긴 뒤 (ALB·ACM 다음)

```bash
DB_HOST=10.20.20.147 ALLOWED_HOSTS=<도메인> CSRF_TRUSTED_ORIGINS=https://<도메인> bash /srv/haven/current/안민수/server/web-setup.sh
bash /srv/haven/current/안민수/server/deploy.sh <지금과 같은 commit>
```

- ALB 상태 검사: 경로 `/healthz`, 포트 80. Nginx가 `/healthz`만 Host를 첫 `ALLOWED_HOSTS`로 바꿔 넘기므로 ALB가 IP로 검사해도 통과한다.
- HTTPS 뒤 `SECURE_PROXY_SSL_HEADER`(앱이 "원래 요청이 HTTPS였다"를 아는 설정)는 요찬과 `신요찬/앱계약.md`로 맞춘다. 맞추기 전에는 HTTPS에서 CSRF 403이 나면 이것부터 의심한다.

## 5. 실패하면 볼 곳

| 증상 | 볼 곳 |
|---|---|
| deploy.sh 실패 | 스크립트가 이전 release로 되돌림. `journalctl -u haven -n 100`, `/srv/haven/releases/` |
| healthz 실패 | `systemctl status haven nginx`, `journalctl -u haven -n 100`, `/var/log/nginx/error.log` |
| DB 연결 실패 | db-1 `systemctl status postgresql`, `/etc/postgresql/16/main/pg_hba.conf`, SG(Web→DB 5432) |
| SSM 비밀값 못 읽음 | NAT가 내려가 있는지(21시 이후?), EC2 Role `haven-ec2-ssm-role`에 `ssm:GetParameter` |
| pip/apt 실패 | NAT 상태 (`morning.sh` 했는지) |
| 백업 S3 거부 | 서버 Role의 `s3:PutObject`/`GetObject` (`db-backups/*`) → 보람 |
| 400 Bad Request | `ALLOWED_HOSTS`에 접속한 이름이 없음 → web-setup.sh 다시 |

**하면 안 되는 것:** 운영 DB `haven`에 restore (스크립트가 테이블이 있으면 거부하게 되어 있음), migration 되돌리기, 비밀값을 명령 인자나 로그에 넣기.
