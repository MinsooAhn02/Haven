# 결정 기록 요약

날짜별 원본은 `docs/조장_운영기록/2026-11-08.md` ~ `2026-11-10.md`, AWS 결정은 `docs/AWS_운영결정.md`. 대화 원문은 올리지 않고 정리본만 남긴다.

## 1. 운영 방식

| 결정 | 이유 |
|---|---|
| 날짜별 시간표 대신 사람마다 주력 + 대기열, 저녁에 다시 배정 | 한 사람이 막히면 다른 사람이 기다리던 문제 |
| 현황은 `TASK_TODO.html` 한 곳 | md가 길어 누가 막혔는지 안 보임 |
| main 직접 push 금지(조장 기록만 예외), 본인 브랜치 → PR | 무료 비공개 레포라 브랜치 보호를 켤 수 없음(API 403) → 규칙으로 운영 |
| 병합 후 각 브랜치에 main을 merge commit으로 넣기, force push 금지 | 개인 브랜치를 계속 쓰므로 이력 보존 |
| 짝 리뷰 + PR에 일부러 실패시킨 거부 시험 필수 | 병합 판단이 조장 한 명에 몰리지 않게. AI가 쓴 코드는 시험을 통과해도 틀릴 수 있음 |
| 같이 정할 판단은 회의 없이 조장이 바로 결정 | 회의 대기 제거 |
| `done`은 실제로 돌려 본 것만 | PR 병합·CI 통과와 실제 동작을 구분 |
| 팀 공지는 한 글, "pull 받고 TODO 이어서", 문제·경고만 `@이름` | 다 같이 읽는 글이라 확인·칭찬 문구는 잡음 |

## 2. AWS·서버

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 서울 리전, 계정당 $100, NAT 1 + S3 Gateway Endpoint | 비용과 설계 단순성 | NAT 없이(설치·SSM 불가), 인터페이스 엔드포인트(비용) |
| t3.small 2대, gp3 20GB | 1GB 메모리로는 Django·PostgreSQL이 빠듯함 | t3.micro |
| 매일 밤·주말 NAT 삭제 + EIP 해제 + EC2 중지 | 하루 약 $0.9 절약, 매일 재구성 연습 | 평일 상시 유지 |
| AWS 작업은 결정 문서 범위면 사전 승인, 되돌릴 수 없는 삭제만 그때 확인 | 건별 승인이 병목 | 건별 승인 |
| 코드는 web-1이 읽기 전용 deploy key로 GitHub에서 받음 | AWS 변경 없음, 개인키가 서버 밖으로 안 나감 | S3 경유, 손으로 복사 |
| 비밀값은 SSM Parameter Store SecureString `/haven/*` | Git·명령 인자·로그에 안 남음, 계정 이전에도 같은 방식 | `.env` 파일 복사 |
| DB 역할 분리: `haven_owner`(migrate) / `haven_app`(CRUD만) | 운영에서 앱이 테이블 구조를 못 바꾸게. 개발 DB도 같은 구조 | 한 계정 |
| 백업 버킷 `haven-backup-<계정ID>`, manifest를 마지막에 올림 | 이름 충돌 방지, manifest 있는 것만 완전한 백업 | |
| 복원은 격리 DB·격리 폴더에만, 운영 DB 덮어쓰기 금지 | 복원 연습이 운영 데이터를 망치지 않게 | |
| Nginx 본문 한도는 앱보다 조금 크게 (16k / 3m) | 경계값 요청을 앱이 413으로 처리해야 요청 로그가 남아 혁민 시험이 유효 | 앱과 같은 값 |
| 도메인: 저렴한 도메인 + Cloudflare DNS | 무료 서브도메인은 ALB·ACM 검증에 못 씀. AWS 밖 DNS는 계정 이전에 유리 | 무료 도메인, ALB 기본 주소 + 자체 서명 인증서 |
| (11/10 변경) 도메인은 민수 GitHub 학생 혜택 → **민수가 가비아에서 저렴한 도메인 구매**로 변경, DNS는 민성 Cloudflare | 학생 혜택 승인이 11/13 낮이라 목요일 HTTPS 일정에 못 맞춤. DNS를 민성에게 넘기면 민수 없이 관리 가능 | 금요일 오후에 HTTPS 붙이기 |
| (11/11 변경) **도메인 `havencloud.shop`은 민성이 직접 구매** | 등록·DNS를 민성이 다 가져 민수 없이 관리 가능 | 민수 가비아 구매 후 빌려주기 |
| 레포는 민수 개인 계정 그대로 (11/10) | 협업자 추가·브랜치 보호·삭제 계획 없음, Actions 설정 끝. admin 필요한 건 Deploy key 정도 | Organization 이전 |
| 조장 이민성, 수 첫 배포도 민성 실행 (11/10) | 민수가 빠질 예정. 있는 동안 한 번 끝까지 해 보기 | 민수가 배포 후 문서로만 인계 |

## 4. 지켜 온 규칙

- 커밋·PR에 AI 표기(Co-Authored-By 등)를 넣지 않는다.
- 비밀번호·키·토큰은 Git·Discord·문서에 쓰지 않는다. 개발 DB 비밀번호는 각자 `pgpass.conf`에만 둔다.
- 브라우저에 자격 증명을 Claude가 대신 입력하지 않는다. 로그인·MFA는 본인이 한다.
- force push 금지.
- 되돌릴 수 없는 AWS 삭제는 조장 확인 후.
- 다른 사람 폴더는 고치지 않는다 (코멘트로 덧붙이기만).
- 조장 기록(현황판·운영기록)만 main 직접 push, 코드는 PR.
- 팀에 공유하는 글에 "일정을 앞당겼다/압축했다/두 배로 했다"는 표현을 쓰지 않는다.
