# 민수가 빠진 뒤 지원 범위

민수는 끝날 때까지 팀원으로 남는다. 개인 사정으로 코딩·배포·리뷰는 하지 않고, 레포(admin)만 지원한다. 민수의 폴더·기록·AWS 계정 `minsoo`는 그대로 둔다.

## 1. GitHub 레포 (`MinsooAhn02/Haven`)

- 레포는 민수 개인 계정에 그대로 둔다. 개인 계정 레포는 admin이 소유자 한 명뿐이다.
- 팀원 5명 + 조교님 2명은 write 권한이다. **PR 병합, 브랜치 push는 민성이 혼자 할 수 있다.**
- admin(민수)만 할 수 있는 것: 협업자 추가·삭제, Deploy keys 등록, 레포 설정·Actions 설정 변경, 레포 삭제·이름 변경.
  - 첫 배포의 Deploy key는 11/11에 민수가 등록한다.
  - 서버를 다시 만들어 deploy key가 바뀌면 민수에게 새 공개키를 보내 등록을 요청한다.
- 브랜치 보호는 무료 비공개 레포라 켤 수 없다. Actions는 이미 설정되어 있다.

## 2. 도메인

- **`havencloud.shop` — 이민성이 직접 구매 (11/11).** 등록 업체 계정과 DNS 모두 민성 관리라 민수 지원은 필요 없다.
- DNS를 Cloudflare(무료)로 옮길지, 등록 업체 DNS를 그대로 쓸지는 민성이 정한다. 어느 쪽이든 CNAME 레코드만 추가할 수 있으면 된다.

순서:
1. ACM 인증서 요청 (`havencloud.shop`, 필요하면 `www.havencloud.shop`, DNS 검증) → ACM이 주는 CNAME을 DNS에 추가
2. ACM 상태가 Issued가 되면 ALB HTTPS 리스너(443)에 연결, HTTP 80은 HTTPS로 전환만
3. DNS에 `havencloud.shop` → ALB DNS 이름 (루트 도메인은 CNAME이 안 되는 업체가 있음: Cloudflare는 CNAME flattening으로 가능, 안 되면 `www`를 쓰고 루트는 전환)
4. 03 문서 4번대로 `ALLOWED_HOSTS=havencloud.shop`, `CSRF_TRUSTED_ORIGINS=https://havencloud.shop` 넣고 재배포

Cloudflare를 쓰면 레코드는 모두 **DNS only(회색 구름)**. 프록시를 켜면 인증서·WAF 시험 결과가 Cloudflare 기준으로 바뀌어 AWS WAF 시험 해석이 꼬인다.

## 3. 연락

- 레포 요청은 Discord로 민수에게. 바로 답하지 못할 수 있으니 하루 여유를 두고 요청한다.
- 민수 AWS 계정 `minsoo`는 그대로 둔다(MFA 등록됨). 민수는 팀원으로 남는다.
