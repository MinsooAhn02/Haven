## 1. GitHub 레포 (`MinsooAhn02/Haven`)

- 레포는 민수 개인 계정에 그대로 둔다. 개인 계정 레포는 admin이 소유자 한 명뿐이다.
- 팀원 5명 + 조교님 2명은 write 권한이다. **PR 병합, 브랜치 push는 민성이 혼자 할 수 있다.**
- admin(민수)만 할 수 있는 것: 협업자 추가·삭제, Deploy keys 등록, 레포 설정·Actions 설정 변경, 레포 삭제·이름 변경.
  - 첫 배포의 Deploy key는 11/11에 민수가 등록한다.
  - 서버를 다시 만들어 deploy key가 바뀌면 민수에게 새 공개키를 보내 등록을 요청한다.
- 브랜치 보호는 무료 비공개 레포라 켤 수 없다. Actions는 이미 설정되어 있다.

## 2. 도메인

- 민수가 **가비아**에서 저렴한 도메인을 구매해 프로젝트 끝(2027-04-20)까지 빌려준다. 가비아 계정은 민수 명의다. 1년 뒤 갱신은 하지 않아도 된다.
- DNS는 **민성 Cloudflare 계정(무료)** 으로 넘긴다. 이후 레코드 추가(ACM 검증 CNAME, ALB 연결)는 민성이 혼자 한다. 가비아 DNS는 쓰지 않는다.
- 도메인 이름: (구매 후 여기에 기록)

순서:
1. 민성: Cloudflare 가입 → Add a site → 도메인 입력 → Free → Cloudflare가 주는 네임서버 2개를 민수에게 전달
2. 민수: 가비아 → My가비아 → 도메인 관리 → 해당 도메인 → 네임서버 설정 → "타사 네임서버 사용"에 그 2개 입력 → 저장
3. 민성: Cloudflare에서 Active 확인 (몇 분~몇 시간)
4. 민성: ACM 인증서 요청 (DNS 검증) → ACM이 주는 CNAME을 Cloudflare에 추가 (**프록시 끄기, DNS only**)
5. 민성: ALB HTTPS 리스너에 인증서 연결 → Cloudflare에 `CNAME <도메인 또는 www> → <ALB DNS 이름>` (DNS only)
6. 민성: 03 문서 4번대로 `ALLOWED_HOSTS`·`CSRF_TRUSTED_ORIGINS` 넣고 재배포

Cloudflare 프록시(주황 구름)를 켜면 인증서·WAF 시험 결과가 Cloudflare 기준으로 바뀌어 AWS WAF 시험 해석이 꼬인다. 모두 **DNS only**로 둔다.
