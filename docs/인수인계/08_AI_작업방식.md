# AI 작업 방식

민수는 조장 일 대부분을 Claude Code로 했다. 민성의 AI가 같은 방식으로 일하도록, 실제로 쓰던 습관과 막혔던 지점을 적는다. 06의 프롬프트와 같이 쓴다.

## 1. 원칙

- **확인한 것과 안 한 것을 나눠서 보고한다.** "CI 통과", "PR 병합", "실제 서버에서 동작"은 서로 다른 말이다.
- **일부러 실패시켜 본다.** 거부되어야 할 요청(남의 기록 접근, 잘못된 파일, 지우면 안 되는 서버)이 실제로 거부되는지 확인한다. 성공만 확인한 시험은 연결만 증명한다.
- **합쳐서 시험한다.** PR 하나만 보지 않고 main + 관련 PR들을 합친 상태로 돌린다. 서로 필요한 PR(앱 + 화면)은 따로 보면 둘 다 실패하거나 둘 다 통과처럼 보인다.
- **읽기 먼저, 바꾸기는 나중.** AWS는 조회(describe/list/get)로 상태를 본 뒤 바꾸는 명령을 사람에게 보여 주고 승인받는다.
- **팀원 폴더는 고치지 않는다.** 문제가 있으면 PR 코멘트나 그 사람 todo로 넘긴다.
- **기록은 바로 남긴다.** 결정하면 운영기록 "결정과 이유"에 이유와 버린 대안까지 적는다. 대화에만 있는 결정은 다음 사람(또는 다음 AI 세션)이 모른다.

## 2. 자주 쓰던 확인 방법

| 상황 | 방법 |
|---|---|
| 앱 PR | 임시 worktree에 main + PR 합침 → `check`, `makemigrations --check --dry-run`, `test` 전체. 시험 수를 그대로 보고(예: 176개 통과) |
| 화면(템플릿) PR | 테스트 DB에서 실제 뷰를 렌더링해 확인: 작성자/공유받은 사람/다른 사람별로 버튼·폼이 맞게 보이는지, 파일명에 `<img src=x onerror=...>`를 넣어 이스케이프되는지 |
| 셸 스크립트(인프라·배포) | 가짜 `aws` 명령을 PATH 앞에 두고 실행: 정상 경로 + 지우면 안 되는 대상이 섞인 경우 → 하나도 안 지우고 멈추는지 |
| 서버 스크립트 | WSL Ubuntu-24.04에서 `안민수/server/test-wsl.sh`, `test-backup-wsl.sh` (서버와 같은 OS) |
| IAM 정책 PR | 조건(태그·이름)을 실제 자원 목록과 대조해 "의도보다 넓은지" 확인. 실제 허용·거부는 해당 사람이 콘솔/CLI로 시험 |
| 현황판 | `node --check`로 DATA JS 문법 확인 (01 문서 3-2) |

## 3. 로컬 시험 환경

```bash
# 레포 루트에서, 앱 시험용 환경변수 (값은 시험 전용, 실제 비밀값 아님)
export DJANGO_SECRET_KEY=test-only DJANGO_DEBUG=0 DJANGO_ALLOWED_HOSTS=testserver,localhost \
       DB_NAME=haven_dev DB_USER=haven_owner DB_HOST=localhost PYTHONUTF8=1 \
       HAVEN_UPLOAD_DIR="$(mktemp -d)"
cd 신요찬/app && python manage.py test -v 1
```

- 개발 DB는 `안민수/dev-db-setup.ps1`로 만든 로컬 PostgreSQL 16. 비밀번호는 `%APPDATA%\postgresql\pgpass.conf`에만 있고 Django가 자동으로 읽는다.
- 의존성은 `pip install -r 안민수/앱통합_초안/requirements.txt` + 앱 PR이 추가한 것(예: `pypdf`). 빠지면 시험 몇 개가 import 오류로 실패한다.

## 4. Windows에서 막혔던 것

| 증상 | 해결 |
|---|---|
| `python3`가 멈춤 (Microsoft Store 안내 프로그램) | `python` 또는 `py -3.13` 사용 |
| `manage.py shell < 파일`이 출력 없이 끝남 | `manage.py shell -c "exec(open(r'<윈도우 경로>').read())"`, Git Bash 경로는 `cygpath -w`로 변환 |
| 테스트 DB가 남아 있다며 입력을 기다리다 EOFError | 직접 돌리는 스크립트에서는 `DiscoverRunner(interactive=False)` |
| `aws.exe` 출력 끝에 `\r`이 붙어 비교가 틀림 | 출력에서 `\r` 제거 (`tr -d '\r'`). 민성 `이민성/infra/common.sh`에 이미 반영 |
| 한글 경로가 `"\354\225..."`로 보임 | `git -c core.quotepath=false ...` |
| 셸 스크립트 줄바꿈 | `안민수/server/.gitattributes`, `이민성/infra/.gitattributes`가 LF로 고정. Windows 편집기로 저장해도 커밋은 LF |

## 5. 사람에게 넘기는 것

AI가 하지 않고 사람이 직접 하는 것:
- 로그인·MFA·비밀번호 입력 (브라우저, AWS 콘솔, Session Manager)
- 서버 안 명령 실행 (AI는 붙여넣을 내용과 sha256을 만들어 주고, 사람이 실행해 결과를 붙여 넣음)
- 되돌릴 수 없는 삭제 승인
- Discord 실제 발송 (AI는 초안만)
