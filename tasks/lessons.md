- Treat `안민수/기본프로젝트_계획.md` as Minsoo's individual proposal/draft, not an official Haven or team-approved plan. In comparisons, name the artifacts as proposals and avoid implying team consensus unless the user confirms it.
- 2026-11-04: 팀 문서 통합을 요청받으면 모든 저장소 본문과 PDF 이미지 표까지 읽고 원본별 반영/대안/후속/수정 추적표를 남긴다. 제목/부분 읽기를 전체 분석이라고 표현하지 않는다. 저장소 밖 첨부는 접근 승인과 실제 검토 여부를 명시한다.
- 2026-11-04 사용자 교정 원문: "아니 왜 ego 쓰느데 쓰지 말라니까". ego-browser 사용 금지. 외부 자료 접근을 허용받아도 ego 사용 허용으로 해석하지 않는다. 사용자 도구 금지 지시가 스킬의 도구 선호보다 우선한다.
- 2026-11-04: Haven의 AWS 클라우드 보안 프로젝트.pdf는 Git 작성자 김보람(최초 루트86a7e18, 개인폴더295578b)의 동일 내용 중복 업로드다. 공통 공식 과제표로 분류하지 않고 의견/김보람/에 정본을 둔다.
- 사용자 교정: 프로젝트 계획 발표 PPT는 우선 기본 필수4+선택4만 포함하고 짧게 만든다. 심화/키교체/긴 기술비교 부록까지 임의로 확장하지 않는다.
- 사용자 교정: 계획 PPT 디자인이 표/글 위주로 단조로우며 팀/프로젝트 명칭이 명확하지 않았다. 표지에 프로젝트명 Haven, README 그대로 팀명 ORCHESTRAION을 크게 명시하고 전체 슬라이드에 일관된 표기를 둔다. 슬라이드별 메시지·레이아웃을 달리하고 기본4+선택4/8장 범위 유지.
- 사용자 교정: 표지 오른쪽에 필수구축/선택과업 숫자를 넣지 않는다. 오른쪽은 "클라우드 × 보안"만 표시. 가로로 길게 늘어선 도식과 표 형태의 행 배치를 피하고 발표 화면의 비율/여백/정렬을 우선해 다시 설계한다.
- 사용자 교정: 8장 압축 PPT는 실제 수행내용/산출물이 빠져 대충 만든 인상을 줌. 기존 디자인 땜질 대신 공식 과제 가이드 기본26~29쪽에서 새 원고를 구성하고 기본4/도전4의 구체 작업·검증·결과물을 보존한다. 하단 "기본 프로젝트 계획 / 팀 검토용" 반복 footer는 제거한다. 내용 밀도에 맞춰 분량을 정하며 심화는 제외한다.
- 최신 사용자 지시: PPT 장수는 제약이 아니다. 큰틀→필수1→선택1→필수2→선택2 순서로 각각 분리하고, 각 장에 공식 주어진 조건과 팀의 기술/구현 방법을 명확히 연결한다. 필요한 설명도는 중간 별도 장으로 추가한다. 이전8장/10장 제한보다 이 지시가 우선.
