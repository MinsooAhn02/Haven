# Haven 기본 프로젝트 목표 체크표

기준: 프로젝트 가이드 PDF 26~29쪽. 구성: A안(AWS WAF + Prowler CLI + ZAP + 자체 Python/boto3 점검).
현재는 계획 단계이며 구현 목표는 모두 미완료입니다. 심화는 이번 체크표에 포함하지 않습니다.

## 완료 표시 방법

증거 경로에 실제 설정·코드·실행 결과·보고서 위치를 적고 완료 조건을 확인한 뒤, 아래 체크박스를 완료로 바꿉니다. 설치 성공이나 AI가 생성한 코드만으로 완료 처리하지 않습니다. 미실행·권한 부족·판정 불가를 정상으로 처리하지 않습니다.

## 완료 체크

- [ ] B1 — Web·DB 동작 및 필수 산출물 확인
- [ ] C1 — 도메인·메일 연동 및 산출물 확인
- [ ] B2 — IAM 사용자·그룹·정책 및 시험 확인
- [ ] C2 — 최소 권한 개선 전후 확인
- [ ] B3 — 네트워크 허용·거부 및 우회 차단 확인
- [ ] C3 — 자체 자동점검 코드·시험·보고서 확인
- [ ] B4 — AWS WAF·서버 정책 적용 및 로그 확인
- [ ] C4 — 정책 개선·정상/공격 대조·재시험 확인

## 공통 검증 규칙

- Prowler는 프로젝트와 관련된 검사만 선정하고 검사 범위·버전·오류를 기록합니다. 자체 점검 코드와 역할을 구분합니다.
- ZAP Baseline은 탐색+수동적 분석입니다. 능동 시험은 팀 실습 서비스의 정해진 범위에서 수행하고, 로그인 여부와 도달한 화면을 기록합니다.
- WAF가 요청을 막았다는 결과와 앱 취약점을 수정했다는 결과를 구분합니다. 정상 요청 회귀 시험을 함께 수행합니다.
- 위험 설정은 fixture·모의 응답 또는 격리된 시험 환경으로 검증합니다. 증거를 만들기 위해 관리/DB 포트를 인터넷 전체에 열지 않습니다.
- 결과에는 시험 대상·설정/코드 버전·조건·기대 결과·실제 결과·증거를 남깁니다. 미리 성과 수치를 작성하지 않습니다.
- 계정 비밀값·키·원문 민감정보는 코드와 결과물에 넣지 않습니다.

## 담당 배정 전 논의할 사항

서비스 시나리오, 예산/리전, 비공개 서버 관리 경로, WAF 과업 인정 범위를 먼저 정합니다. 담당자와 일정은 아직 배정하지 않았습니다.

개인 기여 제안: 안민수는 점검 기준 설계 → 자체 boto3 점검 구현 → 개선 전후 검증을 하나의 기술 작업으로 맡을 수 있습니다. 팀 역할 확정은 아닙니다.
