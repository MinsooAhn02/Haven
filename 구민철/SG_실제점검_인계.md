# SG 실제 점검 인계 — 구민철 (실행·대조 담당)

> 이 문서는 조장이 받은 인계 초안을 그대로 옮긴 것이다. 7장 이후는 아직 작성되지 않았다(조장 확인 필요). 도구의 live 모드는 아직 구현되지 않았고(현재 fixture 모드만), 구현은 이민성이 한다.

## 1. 무엇을 하는가
AWS에 실제로 걸려 있는 보안 그룹(SG) 규칙을 읽기 전용으로 가져와서, 설계의 기대 규칙과 비교해
"열면 안 되는 연결이 열려 있지 않은지" 판정하고 기록한다. (과제: 기본 3 도전 "개방 포트 자동 점검")

## 2. 역할
| 사람 | 맡는 일 |
|---|---|
| 이민성 | 도구(network_audit.py)에 live 모드 구현·시험·병합, 실행 방법·VPC ID 전달 |
| 구민철 | 실제 수집·판정 실행, 결과를 설계와 대조, 기록 |
| 김보람 | 실행에 필요한 IAM 권한 부여 |

## 3. 먼저 읽을 것
- docs/구현명세/기본프로젝트_구현명세.md 5장 (판정 규칙 SG-01~06)
- 이민성/network/설계.md 4절 (SG 3개 sg-alb·sg-web·sg-db의 허용 규칙 = 정답)
- 이민성/sg_audit/README.md (도구 사용법, 판정 4가지)
- 이민성/sg_audit/baseline.json (도구가 쓰는 기대 규칙)

## 4. 판정 읽는 법
| 판정 | 뜻 | 종료 코드 |
|---|---|---|
| PASS | 설계대로 열려 있음 | 0 |
| FAIL | 열면 안 되는 연결이 열림 (예: DB 5432가 인터넷 전체에) | 1 |
| ERROR | 읽지 못함 (권한 없음·수집 실패·입력 오류). 절대 통과로 세지 않음 | 2 |
| UNKNOWN | 정보가 부족해 결론을 못 냄 (예: 어느 서버에 붙었는지 모름) | 3 |

## 5. 준비
- [ ] 김보람님이 권한 추가 완료했다고 알려 줌
- [ ] `python -m pip install boto3`
- [ ] `aws sts get-caller-identity` → 본인 IAM 사용자 확인 (root 금지)
- [ ] 이민성에게 VPC ID와 live 모드 병합 커밋 받기 → `git pull`

## 6. 실행 (live 모드 병합 뒤, 평일 09~21시)
    cd 이민성/sg_audit
    python network_audit.py live --region ap-northeast-2 --vpc-id <VPC> --profile <내 프로필> --baseline baseline.json --output-dir out/live-<날짜시각>
    echo $?          # 종료 코드 기록
- 기대: PASS(0). 다른 결과면 결과 파일의 해당 규칙과 설계.md 4절을 비교해 원인을 적는다
- 일부러 실패 시험 1개: 권한 없는 프로필(또는 존재하지 않는 프로필)로 실행 → ERROR(2) 확인
- output-dir는 매번 새 이름 (덮어쓰기 안 됨)

## 7. 대조와 기록
- 결과(out/…)의 SG별 판정을 설계.md 4절 표와 한 줄씩 (이하 작성되지 않음)
