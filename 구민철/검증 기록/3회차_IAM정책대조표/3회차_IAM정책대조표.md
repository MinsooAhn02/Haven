## 1. 판정 기준

| 표시 | 뜻 |
|---|---|
| **일치(재조회)** | AWS에 저장한 뒤 **다시 열어 본 전체 JSON**과 저장소 JSON을 대조해 일치한다고 기록됨. 마지막 수정 이후에 대조함 |
| **일치(전수)** | 11/12 CloudShell 추출본(`haven_iam_export.zip`)과 대조한 결과로 일치. 그 뒤 수정 기록 없음 |
| **입력만 기록** | AWS에 **입력한** JSON을 저장소에 기록했다는 기록만 있고, 저장 후 재조회 대조 기록은 없음 → **UNKNOWN** |
| **대조 대상 아님** | 과거 설계·초안 보존본(현재 적용 정책은 다른 번호), 또는 AWS 관리형 정책 |
| **기록 부족** | 적용 여부나 대조 기록을 찾지 못함 → **UNKNOWN** |

- JSON의 계정 번호는 저장소에서 `${ACCOUNT_ID}`로 바꿔 적었다(11/13·11/17 보람 정리). AWS 저장본과의 이 차이는 의도한 것이라 불일치로 세지 않는다.

## 4. 한계

- 구민철은 IAM 콘솔을 볼 수 없어, 27번을 빼면 보람 기록을 옮긴 것이다(보고 기준).
- 마지막 대조 이후 AWS에서 정책을 바꿨다면 이 표에 반영되지 않는다. 11/12 전수 대조는 그 시점의 스냅샷이다.
- 정책 내용이 같다는 것과 권한이 의도대로 허용·거부되는지(실환경 시험)는 다르다. 실환경 시험 결과는 이 표의 범위가 아니다(보람 4회차 "담당자별 권한 허용·거부 시험 최종 대조").
- 07·11·14번처럼 현재 AWS에 연결돼 있는지 기록이 없는 것은 연결 여부를 확인해야 판정할 수 있다.
