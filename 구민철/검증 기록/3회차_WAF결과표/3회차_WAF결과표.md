## 7. 새로 확인된 위험: WAF 로그의 본문 조각 (SEC-53)

- 규칙에 걸린 요청은 WAF 로그 `matchedData`에 **요청 본문 일부가 평문으로** 남는다. 가림 설정은 헤더·URI·쿼리만 되고 본문은 안 된다. 11/16·17 로그인·가입 8건의 로그에 비밀번호가 남아 있었다(값은 이 문서에 적지 않는다).
- **조장 결정(11/20):** 보관 30일, 30일이 지난 원본은 혁민이 저장소 밖에 개인 보관, 조회는 혁민 정책만. 분석할 때 `matchedData`를 문서에 옮기지 않는다.
- 로그인·가입의 `SQLi_BODY` 예외는 **차단만 막을 뿐 기록은 막지 않는다.** `SQLi_BODY`는 Count로 남아 계속 WAF 로그에 기록되므로, 예외를 적용해도 **이 위험은 줄지 않는다**(혁민 확인, 조장 11/20 지적). 보관 기간·조회 권한 제한(위 조장 결정)으로 관리한다. 11/25 4단계로 Count가 된 `GenericLFI_BODY`·`SQLiExtendedPatterns_BODY`도 같은 이유로 걸린 요청은 계속 기록된다고 본다(구민철이 로그로 직접 확인하지 않음).

## 9. 한계

- 혁민 보고와 시험결과 문서, 조장 운영기록을 옮긴 것이다. 구민철이 WAF 로그를 직접 조회하거나 시험을 다시 실행하지 않았다.
- 시험 요청 기준의 관찰이며 **방어율이 아니다.** 관리형 규칙의 탐지는 시험 문자열에 따라 달라진다.
- 혁민 CLI의 판정 칸은 `manual_required`(UNKNOWN)이고, PASS는 HTTP 결과와 로그를 보고 사람이 내렸다(혁민 보고).
- ALB 앞 WAF는 본문 앞 8KB만 검사한다.
- 원본 로그·결과(`output/`)는 계정 번호와 IP가 들어 있어 저장소에 없다.
- 24시간 관찰 기간에 실제 사용자는 없었다. 해외 스캐너와 팀 시험 요청 기준이다.
- 4단계 오탐 재확인은 11/24 탐색에서 찾은 입력 10종 기준이다. 같은 규칙에 걸리는 다른 모양의 입력은 다시 찾지 않았다(혁민).
