## 1. 읽는 법

### 1.1 판정

| 판정 | 뜻 |
|---|---|
| **적용 · 시험** | Haven에 해당 기능이 있고, 이 요구를 확인하는 시험이 있다. "이 시험이 이 범위까지 확인했다"는 뜻이지 요구 전체를 만족한다는 뜻은 아니다. |
| **적용 · 설정만** | 설정·프레임워크(Django) 기본 동작이나 문서로 처리되고, 이를 직접 확인하는 시험은 없다. |
| **적용 · 미충족** | 해당하는 요구인데 Haven이 만족하지 않는다(기능 없음, 일부만 만족, 의도한 예외). |
| **제외** | Haven에 해당 기능 자체가 없어 요구가 적용되지 않는다. 장·절 단위로 묶어 이유를 쓴다. |
| **확인 필요** | 판정에 필요한 사실을 확인하지 못했다. 한계 칸에 누구에게 무엇을 확인하면 되는지 적었다. |

### 1.2 증거 표시

- **[직접]**: 구민철이 운영 사이트에서 직접 시험하거나 대조한 증거
- 표시 없음: 팀원(요찬·혁민·조장·푸른·보람)이 시험하고 기록한 증거(**보고 기준**). 구민철은 기록과 파일 위치를 대조했다.
- 레벨(L1~L3)은 원문 표기 그대로다. Haven의 목표 레벨은 정해지지 않아 레벨로 적용·제외를 나누지 않았다.

## 8. CI-01~03 연결

ASVS 5.0.0에는 CI 파이프라인 자체를 다루는 장이 없다. 그래서 CI 시험이 뒷받침하는 ASVS 요구를 연결하고, 직접 대응하는 요구가 없는 것은 그렇다고 적는다.

| 시험 ID | 내용 | 연결한 ASVS | 증거 | 한계 |
|---|---|---|---|---|
| CI-01 | 고정 환경(PostgreSQL, Python 3.12·3.13)에서 앱 테스트 실행, 0건이면 실패 | **직접 대응 요구 없음.** 위 표의 자동 테스트 증거 전체를 재현 가능하게 함 | `.github/workflows/ci.yml` `app-tests`, `안민수/앱통합_초안/require_tests_ran.sh`, 요찬 4회차 6장(각 240개 통과) | GitHub Actions는 11/11부터 팀 규칙으로 꺼져 있어 이후 증거는 같은 순서의 로컬 실행 결과 |
| CI-02 | Django `check`·`makemigrations --check`, 운영 `check --deploy`, pip-audit | v5.0.0-15.2.1, 15.1.1, 15.1.2, 13.4.2, 3.4.1 | 요찬 4회차 6장, 조장 CI-02·DEP-05 증거 | CI에는 `check --deploy`와 의존성 점검이 없음(운영에서 따로) |
| CI-03 | workflow 권한 `contents: read`, Action을 커밋 SHA로 고정 | v5.0.0-15.2.4 (일부) | `.github/workflows/ci.yml`, `앱계약.md` 1.6, 요찬 4회차 6장(SHA가 v4.4.0·v5.6.0 태그와 같음) | Actions가 꺼져 있어 GitHub 실행 증거 없음 |
