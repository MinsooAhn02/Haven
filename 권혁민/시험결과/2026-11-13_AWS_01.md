### [권혁민] AWS WAF Count 탐지 및 로그 상관분석 검증 완료

**대상:** `https://orchestration-haven.cloud`  
**Web ACL:** `haven-web-acl`  
**시험 일시:** 2026-11-13

**1. WAF 연결 및 로깅 검증**
- ALB 연결 후 CloudWatch 로그 스트림 자동 생성 확인
- 로그 그룹 `aws-waf-logs-haven`에서 실제 요청 기록 확인
- Web ACL 기본 동작 `ALLOW`, 관리형 규칙 3개 그룹 `COUNT` 적용 확인

**2. WAF Count 탐지 시험**
- 정상 `/healthz` 요청: HTTP 200, ALLOW, 탐지 0건 — PASS
- 정상 쿼리 요청: HTTP 200, ALLOW, 탐지 0건 — PASS
- SQL Injection: HTTP 200, ALLOW, `SQLi_QUERYARGUMENTS` 및 `SQLiExtendedPatterns_QUERYARGUMENTS` COUNT — PASS
- XSS: HTTP 200, ALLOW, `CrossSiteScripting_QUERYARGUMENTS` COUNT — PASS
- PROPFIND: HTTP 403, WAF ALLOW, `PROPFIND_METHOD` COUNT — PASS

**3. WAF·Nginx·Gunicorn 로그 상관분석**
- 동일 요청 식별자 및 시각을 기준으로 3개 구간 로그 대조 성공
- PROPFIND 요청: WAF ALLOW → Nginx 403 → Gunicorn 403 확인
- 별도 정상 요청의 `X-Request-ID`가 WAF 로그에 기록되는 것 확인
- Nginx·Gunicorn 로그에서는 URL 식별자를 통한 상관분석 성공

**결론:** AWS WAF 관리형 규칙 3개 그룹 모두 실제 Count 탐지 동작을 확인했으며, 시험한 정상 요청에서는 탐지가 발생하지 않았습니다. WAF부터 애플리케이션까지 요청별 로그 상관분석도 성공했습니다.

현재 WAF는 Count 모드를 유지하며, Block 전환은 추가 관찰 후 검토할 예정입니다.

단, Nginx·Gunicorn 로그의 `X-Request-ID` 헤더 기록은 미확인으로, 향후 개선 사항으로 남깁니다.
