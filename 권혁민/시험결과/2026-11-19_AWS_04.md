# Haven AWS 보안 시험 결과 #04 (저장형 XSS 브라우저 확인)

## 요약

운영 사이트에서 제목·본문·첨부 파일명에 스크립트 모양 문자열을 저장하고, 작성자(A)와 공유받은 사람(B)의 브라우저에서 직접 열어 보았다. **실행된 스크립트는 0건**이고, 모든 문자열이 글자 그대로 표시되었다. SEC-09·10·11·14는 화면 확인 기준으로 **PASS**다. 요찬님 APP-06 자동 시험(서버 HTML 이스케이프)과 같은 결론이다.

| 시험 ID | 확인 내용 | 결과 |
|---|---|---|
| SEC-09 | 제목 저장형 XSS (A 상세·목록) | PASS |
| SEC-10 | 본문 저장형 XSS 6종 (A 상세) | PASS |
| SEC-11 | 공유받은 화면 (B 목록·상세) | PASS |
| SEC-14 | 첨부 파일명 XSS 3종 (A·B 첨부 목록, B 다운로드) | PASS (1종은 앱이 업로드 거부) |

## 1. 시험 정보

| 항목 | 내용 |
|---|---|
| 시험 일시 | 2026-11-19 14:29~16:11 (KST, 중간에 저장소 재수신으로 약 1시간 중단) |
| 시험 대상 | AWS 운영 사이트 (`https://orchestration-haven.cloud`) |
| 목적 | 서버가 이스케이프한 HTML이 **실제 브라우저에서도** 스크립트로 실행되지 않는지 확인 |
| 시험 범위 | 공격 시험 계획서 SEC-09·10·11·14 (기존 시험표 APP-06, SH-01, UP-03/09) |

| 브라우저 | Chrome. A는 일반 창(member_a), B는 시크릿 창(member_b) |
| 시험 계정 | 고정 시험 계정 member_a·member_b, 운영 DB 초기화 없음 |
| WAF 상태 | `haven-web-acl`, 관리형 규칙 그룹 3개 Count, 기본 동작 Allow |

## 2. 시험 방법

1. A가 시험 글 `[HAVEN-MANUAL-XSS 11/19] <script>alert('xss-title')</script>`을 만들고 본문에 아래 6종을 넣었다.
   1. `<script>alert('xss-body-script')</script>`
   2. `<img src=x onerror=alert('xss-body-img')>`
   3. `<svg/onload=alert('xss-body-svg')>`
   4. `<a href="javascript:alert('xss-body-link')">링크</a>`
   5. `{{ 7|add:7 }}` (템플릿 문법이 실행되는지)
   6. `&lt;b&gt;이미 이스케이프된 문자열&lt;/b&gt;` (이중 이스케이프·역이스케이프 여부)
2. A가 B(member_b)에게 글을 공유했다.
3. A가 첨부 파일 3개를 올렸다. 파일명은 아래와 같다.
   - `x' onmouseover='alert(1)' y='.txt` (속성 탈출 시도)
   - `&lt;svg onload=alert(1)&gt;.txt` (엔티티 형태)
   - `<img src=x onerror=alert('xss-file')>.txt` (Windows는 `<` `>`를 파일명에 못 쓰므로 DevTools Console에서 `DataTransfer`로 이름을 지정해 정상 업로드 양식으로 전송)
4. A와 B 화면에서 알림창이 뜨는지 보고, 마우스를 올리거나 다운로드해 보았다. 페이지 소스와 DevTools로 이스케이프 형태도 확인했다.

공격 문자열은 알림창만 띄우는 무해한 문자열이다. 시험은 본인 시험 계정의 시험 글에서만 했다.

### 첨부 파일명 (SEC-14)

| 파일명 | 업로드 | 화면 표시 | 결과 |
|---|---|---|---|
| `x' onmouseover='alert(1)' y='.txt` | 성공 | A·B 글자 그대로. 마우스를 올려도 알림창 없음 | PASS |
| `&lt;svg onload=alert(1)&gt;.txt` | **거부** ("파일 이름을 확인해 주세요.") | 저장되지 않아 목록에 없음 | PASS |
| `<img src=x onerror=alert('xss-file')>.txt` | 성공 | A·B 글자 그대로, 깨진 이미지 아이콘 없음, 알림창 없음 | PASS |

- **페이지 소스:** 파일명은 태그 사이의 글자로만 들어가고 따옴표는 `&#x27;`로 바뀐다(파일명 `<h3>`와 삭제 버튼 글자 모두). 다운로드 링크와 삭제 주소에는 파일명 대신 번호(`/posts/48/attachments/39/…`)만 쓰여, 파일명이 HTML 속성이 될 수 없다.
- **엔티티 이름 거부:** Django는 파일명을 받을 때 HTML 엔티티를 풀어 이름을 고친다. 앱은 고치기 전과 후가 다르면 400으로 거부한다(`신요찬/app/posts/upload_handlers.py`의 `StrictNameMultiPartParser`, 명세 3.4). 의도된 동작이다.
- **B 다운로드:** `<img …>.txt`를 받으면 화면에 열리지 않고 파일로 저장되며 알림창이 없다. 받은 파일 이름의 `<` `>`는 Windows가 다른 문자로 바꾼다.
- **B 권한:** B 첨부 목록에는 다운로드 버튼만 있고 삭제 버튼은 없다(읽기 전용).

## 4. 정리

| 순서 | 작업 | 확인 |
|---|---|---|
| 1 | A가 B 공유 해제 | "공유를 해제했습니다." 표시 |
| 2 | B가 글 상세 새로고침 | 404, 공유받은 목록에서 사라짐 |
| 3 | A가 시험 글 삭제 | 내 기록 목록에서 사라짐, 상세 주소 404 |
| 4 | 로컬 시험 파일 폴더·B 다운로드 파일 삭제 | 완료 |

404는 화면에서 접근할 수 없다는 뜻이다. DB 행과 첨부 파일의 물리 삭제는 확인하지 않았다.

## 5. 한계와 참고

- **수동 확인이다.** 요청 CLI로 실행하지 않아 run_id와 WAF·앱 로그 상관분석이 없다. 화면에서 스크립트가 실행되는지만 판정했다.
- **WAF:** 시험 글 작성과 첨부 업로드 요청은 WAF Count 규칙(예: `CrossSiteScripting_BODY`)에 기록됐을 수 있다. 이 보고서는 WAF 탐지가 아니라 앱 출력 방어를 다룬다. 같은 종류의 WAF 탐지는 `2026-11-19_AWS_03.md`에 있다.
- **범위:** Chrome 한 종류에서만 확인했다. 첨부 파일 **내용**은 다운로드로만 제공되어 브라우저에서 해석되지 않으므로 이번 확인 대상이 아니다.
- **스크린샷:** 페이지 소스 캡처(XSS-6)의 CSRF 토큰 값은 가렸다. 그 밖에 접속 IP, 계정 번호, 비밀번호는 캡처에 없다.
