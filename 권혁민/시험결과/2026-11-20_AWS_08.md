# Haven AWS 보안 시험 결과 #08 (WAF Block 3단계 전후 비교: Common + 업로드 예외, 전환 완료)

## 요약

## 4. 업로드 예외 규칙 직접 확인

XMP 메타데이터 모양의 XML(`<x:xmpmeta xmlns:x="adobe:ns:meta/">…`)이 든 같은 본문을 비로그인 curl로 두 주소에 보냈다(16:36, 가짜 CSRF 값).

| 시각 | 요청 | 응답 | 판단 |
|---|---|---|---|
| 16:36:10 | `POST /posts/new/` | 403, `Server: awselb/2.0` | WAF가 막음. 실제 요청 집계에서 `haven-xss-body-except-upload`로 1건 추가 확인 |
| 16:36:23 | `POST /posts/1/attachments/` | 403, `Server: nginx`(앱의 CSRF 거부) | WAF 통과 — 업로드 예외 동작 |

같은 본문이 주소에 따라 갈렸다. 예외 규칙은 업로드 주소에서만 통과시키고, 나머지 주소의 본문 XSS는 막는다.

## 6. 1~3단계 전체 요약 (SEC-59)

| 단계 | 적용 (KST) | 보고서 | HTTP | 막힘 (누적) | 정상 요청 403 |
|---|---|---|---|---|---|
| 1 KnownBadInputs | 11:50 | `2026-11-20_AWS_06.md` | 181/181 | 6/6 | 0 |
| 2 SQLi + 로그인·가입 예외 | 14:28:22 | `2026-11-20_AWS_07.md` | 187/187 | 25/25 | 0 |
| 3 Common + 업로드 예외 | 15:41:16 | 이 보고서 | 187/187 | 44/44 | 0 |

- **본문 XSS는 8건 모두 사용자 예외 규칙 `haven-xss-body-except-upload`가 막았다**(글 작성·수정, 로그인 반사 XSS). Common에서 `CrossSiteScripting_BODY`를 Count로 뺐기 때문에, 이 규칙이 본문 XSS 방어를 맡는다.
- 같은 시험 묶음을 Count(11/19~20)와 Block 1·2·3단계에 같은 조건으로 실행했고, 각 단계에서 **막혀야 할 요청만 정확히 막혔다.**
- Count 단계에서 찾은 오탐 3가지(`!@#` 비밀번호, XMP PDF, 큰 업로드)는 모두 예외로 처리되어 **Block 뒤에도 정상 동작**한다.
- Block 뒤에도 WAF가 막지 못하는 것(주석형 `admin'--`, 업로드 형식 공격, 본문 8KB 뒤 내용, 업로드의 XSS)은 판단안 4절대로 **앱 검증이 계속 막는다.** 이번 실행에서도 해당 요청은 앱 400·413·화면 이스케이프로 처리되었다.
