# Haven WAF 로그 보관과 11/25 대량 스캔 분석 (2026-11-27)

## 요약

WAF 로그(`aws-waf-logs-haven`) 11/12~11/26분을 **저장소 밖에 암호 압축으로 보관**했다(SEC-53, 보존 30일 대비). 받은 건수는 Logs Insights 집계와 **53,866건으로 일치**한다.

보관 중 **11/25 18:00~20:00 KST에 대만(TW)발 디렉터리 대입 스캔 30,422건**을 발견했다. WAF는 5,229건을 막았고, 통과분은 Host가 우리 도메인이 아니었고, 앱에 닿은 12,611건은 400으로 거부됐다(나머지는 ALB 301로 추정). 스캐너가 Haven에서 받아 간 것은 없다. 다만 **WAF 빈도 규칙이 없어(WAF-05) 대량 요청의 83%가 WAF를 통과**한 실제 사례다.

## 1. 보관 방법

1. `aws login --profile hyeokmin` 뒤 저장소 밖 개인 스크립트(`archive_waf_logs.py`, 저장소에 올리지 않음)로 KST 하루 단위 JSON을 받았다(`aws logs filter-log-events`, 자동 페이지 넘김). 스크립트는 건수·크기만 출력하고 로그 내용은 출력하지 않는다.
2. 11/27은 받는 도중에도 로그가 쌓이는 반쪽 날이라 제외했다. 11/27부터는 다음 보관에서 온전한 하루로 받는다.
3. 같은 범위를 Logs Insights `stats count(*)`로 세어 건수를 대조했다.
4. ZIP AES-256으로 압축하고 압축 파일 테스트를 한 뒤 원본 JSON을 지웠다. 암호는 저장소·채팅에 남기지 않았다.

## 2. 11/25 대량 스캔 분석

IP·요청 본문·`matchedData`는 조회하지 않았다. 시간·나라·판정·경로 개수·User-Agent·Host 일치 여부만 집계했다. 실제 Host 값은 이 문서에 옮기지 않았다.

| 질문 | 조회 | 결과 |
|---|---|---|
| 언제 | 1시간 단위 건수 (11/25) | 18시대 14,549건, 19시대 15,976건 (KST). 다른 시간은 시간당 15~343건 |
| 어디서 | 나라·판정별 건수 (11/25) | TW 30,422건(ALLOW 25,193, BLOCK 5,229). 그 밖의 나라는 모두 합쳐 1,504건 |
| 무엇을 | 경로별 건수 (11/25) | 가장 많은 경로도 `/` 317건뿐. 요청이 서로 다른 경로에 흩어짐 |
| 어떤 도구 | TW 요청의 User-Agent·판정·경로 수 | User-Agent는 **하나**(오래된 Mac 브라우저 흉내). 통과 요청의 경로 **12,543개**. 차단은 Common 3,649건, KnownBadInputs 1,580건 |
| 누구를 노렸나 | TW 통과 요청의 Host가 우리 도메인인지 | **25,193건 모두 우리 도메인이 아님** |
| 앱은 어떻게 답했나 | 같은 시간 `/haven/web` 상태 코드 | 400 12,611건, 404 13건, 200 5건, 302 5건 |

**판단**

- **디렉터리 대입 스캐너다.** User-Agent 하나로 2시간 동안 서로 다른 경로 1만 개 이상을 차례로 요청했다.
- **Haven을 노린 공격이 아니다.** Host가 우리 도메인이 아니었으므로, 도메인을 모른 채 IP나 로드 밸런서 주소로 인터넷을 훑는 스캐너가 우리 ALB에 닿은 것이다.
- **받아 간 것은 없다.** WAF가 알려진 공격 문자열 5,229건을 막았다. 통과해 앱에 닿은 요청(12,611건)은 Django의 Host 검사(`ALLOWED_HOSTS`)가 400으로 거부했다. 같은 시간 200·302는 각 5건으로, 평소 운영 수준이다.
- **통과 25,193건 중 앱 로그에 닿은 것은 약 절반이다.** 경로 수(12,543)와 앱 400 건수(12,611)가 거의 같아서, 같은 경로를 HTTP와 HTTPS로 한 번씩 보내 HTTP 쪽은 ALB가 301로 돌려보낸 것으로 **추정**한다. ALB 접근 로그를 켜지 않아 확인하지는 못했다.
- **우리 시험과 무관하다.** 같은 날 혁민의 4단계 재시험은 10:10~10:26이었다.

## 3. 의미와 한계

- **빈도 규칙 없음(WAF-05)의 실제 사례:** 한 출처가 2시간에 3만 건을 보내도 WAF는 알려진 공격 문자열만 막고 나머지 83%를 통과시켰다. 이번에는 앱의 Host 검사가 막았지만, 우리 도메인으로 같은 스캔이 왔다면 Haven 경로까지 닿았을 것이다. 속도 기반 규칙(같은 출처 5분에 N건 넘으면 차단)이 있었다면 WAF 단계에서 끊을 수 있었다.
- **여러 겹 방어가 동작했다:** WAF(알려진 공격 차단) → 앱 Host 검사(엉뚱한 Host 거부) → 앱 404(없는 경로)가 차례로 막았다.
- **비용:** WAF 요청 요금은 요청 수에 비례하지만 3만 건은 적은 금액으로 보인다. 정확한 금액은 비용 기록(보람)으로 확인해야 한다.
- **한계:** IP를 보지 않아 같은 출처가 여러 IP를 썼는지는 모른다. ALB 접근 로그가 없어 HTTP/HTTPS 나눔은 추정이다.
