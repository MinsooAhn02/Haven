# 2회차 작업 기록 — IAM·예산·백업 구성

**담당:** 김보람 (AWS 계정·IAM·비용/자원 관리)  
**작업 기간:** 2026-11-09 ~ 2026-11-10  
**기준:** 실제 AWS 설정·정책 파일 작성·시뮬레이터·담당자 실제 실행 결과를 구분하여 기록함.

## 2026-11-09 — 예산·팀원 IAM 계정 및 서버 역할 준비

### AWS 예산과 운영 비용
- 당시 AWS 크레딧 **$120**을 프로젝트 운영 예산 **$100**과 비상 예비비 **$20**으로 구분함.
- `Haven-Project-AWS` 비용 예산을 $100로 생성하고 실제 사용 비용 기준 **$50 / $80 / $95** 단계별 경보를 설정함. 이메일 수신자 등록 및 인증 상태 확인.
- Web·DB 서버 각각 `t3.small`, EBS `gp3` 총 **40 GiB**, 평일 **09:00~21:00(12시간)** 운영을 기준으로 NAT·EC2 등의 비용 예측 자료를 작성해 인계함.
- 예상 비용과 AWS 예산 경보는 **실제 청구 금액 또는 자동 지출 차단이 아님**을 별도 명시함.

### 공통 EC2 역할 및 SSM·S3 준비
- 공통 IAM Role `haven-ec2-ssm-role`을 생성하고 `AmazonSSMManagedInstanceCore` 정책을 연결함.
- 인스턴스 프로파일 `haven-ec2-ssm-profile`을 생성하여 위 역할과 연결한 상태를 CLI로 확인함.
- 역할에 `Haven-EC2-SSM-Parameters-Read` 정책을 추가하여 서울 리전의 `/haven/*` 파라미터에 `ssm:GetParameter` 읽기 권한을 부여함.
- EC2 역할에 `Haven-EC2-S3-Backup-Restore` 인라인 정책을 연결하고, S3 `db-backups/*` 경로의 `s3:PutObject`·`s3:GetObject` 범위를 기록함. 당시 **버킷의 실제 생성·백업 복원 시험은 아직 전**이었음.

### 이민성(`minsung`) IAM 계정과 정책
- IAM 사용자 `minsung`을 만들고 최초 로그인 시 비밀번호 변경을 요구하도록 설정함.
- `Haven-Minsung-Infra-Policy`를 생성·연결하여 승인된 서울 리전의 VPC·서브넷·라우팅·SG·NAT·EIP·EC2 구성 작업을 준비함.
- `Haven-Minsung-PassRole-Policy`는 `haven-ec2-ssm-role`을 **EC2 서비스에만 전달**하도록 제한함(`iam:PassedToService = ec2.amazonaws.com`).
- 본인 MFA 정책 `Haven-Minsung-Self-MFA-Policy`와 `IAMUserChangePassword`를 추가함. 콘솔 화면에서 **정책 4개 연결**을 확인함.
- 실제 민성님 MFA 등록·CLI 구축 성공·실환경 허용/거부 검증은 당시 별도 대기 항목이었음.

### 안민수(`minsoo`) IAM 계정과 정책
- IAM 사용자 `minsoo` 생성 및 초기 로그인 시 비밀번호 변경을 설정함.
- `Haven-Minsoo-SSM-Policy`를 연결하여 서울 리전 `/haven/*` 파라미터 읽기·쓰기(`GetParameter`, `PutParameter`)를 허용함.
- 민수님의 최초 콘솔 로그인 성공 보고를 받았고, MFA 목록 조회(`iam:ListMFADevices`)와 CloudShell 권한 부족 문제를 확인함.
- `Haven-IAM-Self-MFA-Password-Policy`, `AWSCloudShellFullAccess`, `Haven-Minsoo-SSM-Policy`, `IAMUserChangePassword`의 **4개 정책 연결**을 콘솔에서 확인함.
- 정책 연결 이후 민수님의 비밀번호 변경·MFA 실제 등록·CloudShell·SSM 시험 결과는 별도 확인이 필요했음.

### GitHub 기록
- 이민성 구축 권한 요청 및 PR #27을 참고해 PassRole, EC2 역할 신뢰, Web/DB 로그, S3 백업, SSM 파라미터, MFA 정책 템플릿을 작성함.
- **PR #29**로 IAM 설계·정책 JSON을 제출함. 계정 ID를 변수로 적은 GitHub 정책 템플릿과 AWS에 실제 저장한 계정 범위는 구별함.
- 당시 AWS 콘솔 접근이 필요하지 않거나 범위가 정해지지 않은 다른 팀원 계정은 임의 생성하지 않음.

## 2026-11-10 — 구축 권한 오류 대응·시뮬레이터 시험·S3 생성

### 민성님 인프라 권한과 검증
- `Haven-Minsung-Infra-Policy`에 `ec2:StartInstances`·`ec2:StopInstances`가 포함된 것을 확인함(서울 리전 및 `Project=Haven`, `Owner=minsung` 조건).
- 누락된 `ssm:DescribeInstanceInformation` 권한을 추가·저장함. 민성님 AWS CLI `2.39.6`, `SignInLocalDevelopmentAccess` 연결 확인; **장기 액세스 키는 발급하지 않음**.
- IAM 정책 **시뮬레이터**로 다음 4건을 확인함.

| 시험 | 확인 결과 | 구분 |
|---|---|---|
| `ec2:DescribeInstances` / 서울 `ap-northeast-2` | 허용 | 시뮬레이터 |
| `ec2:DescribeInstances` / 버지니아 `us-east-1` | 거부 | 시뮬레이터 |
| `iam:PassRole` / 지정 역할 → EC2 서비스 | 허용 | 시뮬레이터 |
| `iam:PassRole` / 동일 역할 → Lambda 서비스 | 거부 | 시뮬레이터 |

- 위 네 결과는 **실제 EC2 생성·중지 명령의 성공을 의미하지 않음**. 민성님 로그인·MFA·STS 및 실제 스크립트 결과는 담당자 확인 대상.
- 민성님 `build.sh`의 VPC 생성 권한 오류를 근거로 인프라 정책 조건을 조정하고 [12번 JSON](../JSON/12_Minsung_Infra_Policy.json)에 반영함. **PR #39 병합** 기록.
- `RunInstances` 점검에서 태그 없는 생성 요청 거부, 공인 IP 할당 요청의 명시적 거부, 기본 SG의 Haven 태그 부재로 인한 거부를 확인함. 시험용 명령과 Haven 태그가 적용된 실제 구축 명령의 조건을 구별함.

### 민수님 SSM 접속 권한·S3 버킷
- `Haven-Minsoo-SessionManager-Policy`를 생성·연결하여 Haven 태그 서버에 대한 `StartSession`, 본인 세션 종료·재개, EC2/SSM 상태 조회 권한을 준비함. 민수 계정의 총 **5개 정책 연결** 확인.
- 서울 리전에 백업 버킷 `haven-backup-ACCOUNT_ID_MASKED`을 생성함. **퍼블릭 접근 모두 차단, ACL 비활성화, SSE-S3 암호화** 설정을 확인함.
- EC2 공통 역할의 `s3:PutObject`·`s3:GetObject` 대상이 `db-backups/*`로 제한되는 것을 확인하고, EC2 역할의 SSM 파라미터 정책 ARN도 실제 계정으로 조정·저장함.
- **버킷 생성/권한 연결은 완료**했지만 민수님의 Session Manager 실접속·S3 백업 파일 업로드·복원 성공 여부는 미확인 상태임.

### 시험용 자원 삭제 권한 안전 제한
- 민성님이 `haven-test` 서버의 태그가 맞음에도 `ec2:TerminateInstances`에서 `UnauthorizedOperation` 오류가 난다고 보고함. 실제 정책 연결 여부와 조건을 별도 점검함.
- EC2 영구 삭제용 [13번](../JSON/13_Minsung_TerminateInstances_Policy.json), 민성 SSM 접속용 [14번](../JSON/14_Minsung_SessionManager_Policy.json), SG 삭제용 [15번 JSON](../JSON/15_Minsung_DeleteSecurityGroup_Policy.json)을 작성하고 **PR #42**로 기록함.
- 처음에는 `Project=Haven`·`Owner=minsung` 조건만으로 실제 운영 서버까지 삭제될 수 있다는 지적을 받아 수정함.
- IAM 사용자 `minsung`에 고객 관리형 `Haven-Minsung-Delete-Policy` 연결을 확인함. 인라인 정책은 2,048바이트 제한 때문에 생성에 실패하여 관리형 정책 방식으로 전환했음.
- **최종 11/10 AWS 적용 확인:** EC2 `TerminateInstances`는 `Project=Haven`·`Owner=minsung`·`Name=haven-test*`를 모두 요구. SG 삭제는 당시 `Project=Haven` 조건으로 기록했으며, **11/11에 시험용 SG만 허용하도록 추가 축소**함.
- 민성님에게 `bash destroy.sh --delete` 사용 금지, 실제 종료 대상 ID·태그를 확인하여 시험용 EC2 한 대만 종료, 운영 서버 `web-1`·`db-1` 유지 확인을 요청함.
- 평일 21시 운영 종료 시에는 `bash night.sh`로 EC2 중지·NAT 삭제·EIP 해제를 수행하는 운영 절차와 인프라 영구 삭제 절차를 분리함. **민성님의 실제 실행 여부는 이 기록으로 확인하지 못함**.
