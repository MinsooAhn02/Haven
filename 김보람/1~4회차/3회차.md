## 2026-11-11 — 3회차 권한·DNS·SES·보안 로그 및 비용 점검

### 1. 시험용 SG 삭제 권한 제한
- 고객 관리형 `Haven-Minsung-Delete-Policy`를 AWS 콘솔에서 수정해 **업데이트 성공**을 확인함.
- 시험용 EC2 영구 삭제 범위(`Project=Haven`, `Owner=minsung`, `Name=haven-test*`)는 유지함.
- `ec2:DeleteSecurityGroup`은 **`Project=Haven`과 `Name=haven-sg-test` 태그 조건을 모두 만족하는 SG**로 제한함. 운영용 `haven-sg-web`·`haven-sg-db`·`haven-sg-alb`를 임의 삭제하지 않도록 범위를 축소한 것임.
- [15번 정책 JSON](../JSON/15_Minsung_DeleteSecurityGroup_Policy.json)을 갱신함. 이는 AWS의 정책 저장 확인이지 실제 삭제 허용/거부 테스트 완료가 아님.
- 실제 시험용 SG 삭제 허용·운영 SG 삭제 거부 시험과 다른 정책을 통한 우회 가능성은 민성님 점검 대기. 조회 당시 `haven-sg-test` SG는 목록에서 발견되지 않았음.

- **정책 연결·저장과 실제 ALB/ACM/Route 53 모든 API 성공은 다름**. 민성님 재시험 결과에 따라 추가 검증이 필요함.

### 3. SES 테스트 메일·도메인 인증
- 서울 리전 SES에서 테스트 발신 이메일 자격 증명이 **확인됨(Verified)** 상태임을 확인하고 **테스트 메일 발송·수신**을 단독 시험함. Django 앱 실제 발송 시험과는 구분함.
- 프로젝트 도메인 `orchestration-haven.cloud`의 SES 자격 증명을 **14:29**에 생성함. 생성 직후는 확인 보류·Easy DKIM 대기 상태였음.
- 민성님이 Route 53에 등록한 **DKIM용 CNAME 3개**를 조회해 확인함. **15:57 민성님 보고**에서 도메인 `Verified`, DKIM `SUCCESS`를 확인함. 보람의 SES 콘솔 완료 화면 직접 재조회는 별도로 기록되지 않음.
- 신요찬님과 Django 실제 메일 발송·수신·실패 시험, SES 샌드박스·발신 권한 점검은 **11/12 진행 예정으로 남긴 항목**이며 이 기록에서는 완료로 표시하지 않음.
- [도메인 DKIM 인증 상세 기록](../SES_도메인_DKIM_인증_2026-11-11.md)과 [PR #58](https://github.com/MinsooAhn02/Haven/pull/58)을 참고.

### 2026-11-12 — 민성님 WAF 야간 유지 비용·IAM 권한 검토 및 답변

AWS WAF IAM 리소스 형식 `managedruleset`은 관련 작업에서 사용될 수 있음. 그러나 정책에 기재된 `arn:aws:wafv2:ap-northeast-2:${ACCOUNT_ID}:regional/managedruleset/*/*`의 **계정 ID는 Haven AWS 계정 번호로 올바르지만**, AWS 제공 관리형 규칙 그룹에 대해 해당 계정 범위를 쓰는 것이 실제 필요한 권한과 일치하는지는 아직 미검증. PR #80에는 `create-web-acl` 성공이 기록되어 있으나, **그 성공이 이 특정 리소스 권한 덕분인지까지는 확인되지 않음**. 임의 변경하지 않고 실제 IAM 평가/오류 내역으로 검증 필요.

- **완료 구분:** 본 항목은 비용 및 권한 **검토·답변 기록**임. Web ACL–ALB 실제 연결 성공, 정책 허용/거부 시험, WAF 실사용 요금 확정으로 처리하지 않음.

### 2026-11-16 — 혁민님 CloudWatch DB 로그 조회 권한 추가

- **요청 및 원인:** PR #116 검토 중 혁민님 계정으로 CloudWatch 로그 그룹 `/haven/db` 조회를 시도했으나 `logs:FilterLogEvents` 권한 부족(AccessDenied)이 발생함. 기존 혁민님 조회 정책은 `/haven/web` 및 WAF 로그 대상이었고, 새로 추가된 DB 로그 그룹은 포함하지 않았음.

- **GitHub JSON 수정 및 대조:** AWS에 저장된 최종 정책과 일치하도록 `김보람/JSON/20_Hyeokmin_CloudWatch_Read_Policy.json`을 수정함. GitHub 파일은 저장소의 기존 계정 번호 표기 규칙에 따라 `${ACCOUNT_ID}` 자리표시자를 사용하며, 권한 구성과 리소스 범위가 AWS 저장본과 동일함.
