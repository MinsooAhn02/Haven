**3. AWS CloudWatch 로그 보관 정책**

- AWS CloudWatch Logs는 로그 그룹에 설정된 보관 기간에 따라 오래된 로그 데이터를 자동 삭제함.
- 30일 보관으로 설정된 경우, 기록된 지 30일이 지난 로그는 자동 삭제 대상이 되며 일반적으로 만료 후 72시간 이내에 삭제됨.
- 자동 삭제되는 것은 보관 기간이 지난 **로그 데이터**이며, 로그 그룹 자체가 자동으로 삭제되는 것은 아님.
- 30일은 AWS가 의무적으로 지정한 기간이 아니라 프로젝트에서 설정한 보관 기간임.

**참고:** [AWS CloudWatch Logs 공식 보관 정책](https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/Working-with-log-groups-and-streams.html)

**4. 로그 압축 보관 계획**

- **예정일:** 2026년 12월 11일
- **담당:** 이민성
- **보관 대상:** Web·DB·WAF·애플리케이션 로그 중 발표 및 보안 검증에 필요한 기록
- **보관 방법:** 필요한 로그를 별도 파일로 저장한 뒤 압축하여 보관
- **보관 목적:** AWS 자원 종료 이후에도 보안 점검 및 시험 결과를 심화 프로젝트 발표 자료로 활용하기 위함

다만 12월 11일 이전에 보관 기간이 만료되는 로그가 있을 수 있으므로, 필요한 과거 기록이 삭제되지 않도록 **로그 만료 시점 확인 및 조기 압축 보관 또는 보관 기간 조정 여부를 담당자와 협의해야 함.**

**5. 심화 프로젝트 최종발표까지 보관할 자료**

- AWS CloudWatch 로그 그룹은 필요한 로그의 압축 보관 및 파일 확인이 완료된 후 삭제 여부를 별도로 결정함.

- 기본 프로젝트 최종발표 및 재시연에서 사이트 접속·DNS가 필요한 동안은 유지하고, 사용 종료 후 삭제하는 방향으로 검토함.
- 호스팅 영역 삭제 전에는 도메인·사이트·메일 인증에 사용 중인 DNS 레코드와 향후 사용 계획을 민성님과 확인할 예정. **호스팅 영역 삭제와 도메인 등록 자체의 해지는 별개임.**

**2. IAM 사용자·역할**

- 발표 및 AWS 자원 종료 작업이 끝날 때까지 필요한 사용자·역할·권한을 유지함.
- 이후 사용하지 않는 IAM 사용자는 콘솔 로그인 차단과 액세스 키 비활성화 등으로 **접근 차단**할지, 최종 확인 후 **삭제**할지 팀원들과 협의하여 결정함. 콘솔 로그인 차단만으로 모든 접근이 차단되는 것은 아니므로 액세스 키·활성 세션도 함께 점검함.
- EC2에 연결된 IAM 역할 및 인스턴스 프로파일은 관련 서버·백업·로그·삭제 작업이 끝난 뒤 정리 여부를 판단함.
- 민성님에게 임시 부여할 삭제 권한은 승인된 종료 작업에만 사용하고, 작업 완료 후 회수할 예정. **AWS 계정 자체 및 루트 사용자는 이 IAM 정리 대상에 포함하지 않음.**

**3. SES 도메인 인증**

- 대상: `orchestration-haven.cloud` SES 발신 도메인 인증(기존 기록상 Verified·DKIM SUCCESS).
- **12월 2일 최종발표·재시연에서 메일 발송 기능을 사용할지** 팀원들과 먼저 확인하고, 필요한 동안 SES 인증 및 관련 DNS 설정을 유지함.
- 메일 발송 시연과 후속 사용이 모두 끝난 뒤 SES 인증 삭제 여부를 결정함. Route 53 호스팅 영역을 먼저 삭제하면 SES 도메인 인증에 필요한 DNS 레코드도 영향을 받으므로 정리 순서를 함께 검토함.

**진행 상태:** 위 세 항목은 보존·삭제에 대한 **검토 의견**이며 최종 확정·실행된 사항이 아님. 보존 기간과 실제 삭제 대상은 팀원들 및 조교님 의견을 반영하여 결정할 예정임. **현재 AWS 자원·IAM·SES 설정 변경 없음.**

**주의:** 보존·종료 승인이 확인되지 않은 AWS 자원은 변경·삭제하지 않음.
