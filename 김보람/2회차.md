- 관리형 정책 `AmazonSSMManagedInstanceCore` 연결.
- 인스턴스 프로파일 `haven-ec2-ssm-profile` 생성 및 해당 역할 연결을 AWS CLI로 확인.

  - `ssm:GetParameter` — 서울 리전의 `/haven/*` 경로 읽기.
  - DB 비밀번호·Django 비밀키 등 **값 자체는 이 문서에 기록하지 않음**.

- `minsung`의 본인 MFA 관리 인라인 정책 `Haven-Minsung-Self-MFA-Policy` 및 AWS 관리형 `IAMUserChangePassword` 연결 완료 화면 확인.
- 사용자 `minsung`에 인프라·PassRole·본인 MFA·비밀번호 변경 **4개 정책이 연결됨**(11/09 사용자 제공 스크린샷).

- 민수님 사용자 `minsoo` 콘솔 로그인 성공 보고. 최초 MFA 화면에서 `iam:ListMFADevices` 거부 및 CloudShell 권한 부족 보고를 수신함.

  - `Haven-IAM-Self-MFA-Password-Policy`(고객 인라인, 본인 MFA 및 비밀번호 관리)
  - `Haven-Minsoo-SSM-Policy`(고객 인라인, `/haven/*` SSM 읽기·쓰기)
  - `IAMUserChangePassword`(관리형, 본인 비밀번호 변경 — 일부 기능 중복 가능)
- IAM MFA/비밀번호 정책의 JSON 초안 `IAM/09_IAM_Self_MFA_Password_Policy.json`와 적용·검증 안내 `IAM/10_Minsoo_CloudShell_권한안내.md`를 GitHub PR #29에 추가.
- **정책 연결은 확인했지만, 민수님이 다시 로그인한 후 실제 MFA 등록·CloudShell 실행·SSM 허용/거부 시험까지 성공했는지는 미확인.**

## 3. 현재 상태 및 주의사항

- **IAM Role·프로파일·일부 IAM 정책 생성/연결은 진행했지만, 실제 EC2/VPC 서버 구축과 권한 시험 완료를 의미하지 않음.**
- 인프라 정책을 `minsung` 사용자에게 연결했으나 실제 구축 권한 검증 전임. 태그/리소스 조건으로 작업이 거부될 가능성은 시험 후 수정.
- S3 백업 버킷 이름 규칙은 운영결정 문서에서 확정됨. AWS EC2 Role에 정책을 연결했으나 버킷 생성·동작 검증 전이며 같은 Role을 Web·DB에 공통 적용한다는 점은 추가 검토 필요.
- IAM 비밀번호·액세스 키·SSM 비밀값은 GitHub와 Discord에 올리지 않음.
- AWS 예산 경고는 자동으로 서버를 중지하거나 NAT를 삭제하지 않음.
