- 인프라 정책을 `minsung` 사용자에게 연결했으나 실제 구축 권한 검증 전임. 태그/리소스 조건으로 작업이 거부될 가능성은 시험 후 수정.
- S3 백업 버킷 이름 규칙은 운영결정 문서에서 확정됨. AWS EC2 Role에 정책을 연결했으나 버킷 생성·동작 검증 전이며 같은 Role을 Web·DB에 공통 적용한다는 점은 추가 검토 필요.
- IAM 비밀번호·액세스 키·SSM 비밀값은 GitHub와 Discord에 올리지 않음.
- AWS 예산 경고는 자동으로 서버를 중지하거나 NAT를 삭제하지 않음.

### 민성님 IAM 정책 시뮬레이터 점검 (실제 CLI 실행과 구분)
| 대상·조건 | 기대 결과 | 보고된 결과 | 구분 |
|---|---|---|---|
| `ec2:DescribeInstances` / `ap-northeast-2` | 허용 | 허용 | IAM 시뮬레이터 |
| `ec2:DescribeInstances` / `us-east-1` | 거부 | 거부 | IAM 시뮬레이터 |

### 민수님 `minsoo` Session Manager 접근
- `Haven-Minsoo-SessionManager-Policy` 인라인 정책을 생성·연결하고, IAM 사용자 권한 화면에서 총 5개 정책 연결 확인.
- 의도: `Project=Haven`인 서울 리전 EC2에만 `ssm:StartSession`, 자신이 시작한 세션에만 `ssm:TerminateSession`·`ssm:ResumeSession`, `ec2:DescribeInstances` 및 SSM 상태 조회.
- 적용 취지를 재현하기 위한 JSON 기록: [11_Minsoo_SessionManager_Policy.json](IAM/11_Minsoo_SessionManager_Policy.json). **실제 정책 허용·거부 및 서비스별 조건 적용 여부는 민수님이 서버 구축 후 점검 필요**.
- 기존 `Haven-Minsoo-SSM-Policy`는 파라미터 `/haven/*` 읽기·쓰기용으로 별도 유지. 콘솔 JSON에 계정 `ACCOUNT_ID_MASKED`이 들어 있는 것 확인(키·비밀값 기록 없음).

### 백업 버킷 생성 및 역할 정책 대조
- S3 버킷 **`haven-backup-ACCOUNT_ID_MASKED` 생성 완료** (버킷 목록 화면 확인).
- 위치: 서울 `ap-northeast-2`. 퍼블릭 액세스 모두 차단, ACL 비활성화, 기본 암호화 SSE-S3 설정을 버킷 생성 화면에서 확인.
- EC2 공통 Role의 `Haven-EC2-S3-Backup-Restore` 정책 JSON 확인: `s3:PutObject`·`s3:GetObject` 범위는 `arn:aws:s3:::haven-backup-ACCOUNT_ID_MASKED/db-backups/*`.
- EC2 Role `Haven-EC2-SSM-Parameters-Read` 정책의 AWS 계정 범위를 실제 계정 `ACCOUNT_ID_MASKED`으로 제한·저장. `minsoo`의 `Haven-Minsoo-SSM-Policy`는 이미 동일 계정 범위 적용을 확인.
- 버킷 생성/권한 연결과 **실제 S3 파일 업로드·복원 시험은 별개**이며 서버 구성 후 민수님이 시험할 예정.
