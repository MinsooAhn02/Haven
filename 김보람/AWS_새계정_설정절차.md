# Haven 새 AWS 계정 설정·인계 절차 (초안)

**작성 기준:** 2026-11-13까지의 Haven IAM·운영 기록  
**담당:** 김보람(IAM·SES·비용 기록), 이민성(조장·인프라 실행), 신요찬(앱 메일 시험), 권혁민(WAF·로그 점검)  
**상태:** **재구축용 점검 절차 초안**. 새 AWS 계정에서 실제 재구축·권한 검증을 완료한 문서가 아님. 기존 계정의 설정을 변경하지 않음.

## 1. 새 계정 시작 전 결정

- [ ] 조장 승인: 새 계정 사용 목적, 서울 리전(`ap-northeast-2`), 예산 상한, 실제 리소스 생성 담당 및 비용 부담 주체 결정
- [ ] 새 계정의 **12자리 계정 ID** 확인. 기존 계정 ID나 ARN을 그대로 복사하지 않음
- [ ] 루트 사용자 MFA·복구 연락처·청구 연락처 설정, 루트 상시 사용 금지
- [ ] 관리자/운영자별 IAM 사용자 또는 역할, MFA, 최소 권한, 계정 접근·회수 절차 확정
- [ ] AWS Budgets/청구 알림, 비용 태그(`Project=Haven`, `Owner` 등), 실사용액 확인 책임자 지정
- [ ] 도메인 이전·기존 계정 병행 운영 여부와 DNS 전환 시점 결정. DNS·백업을 승인 없이 변경하지 않음

## 2. 정책 JSON 이식 시 필수 확인

1. [김보람/JSON](JSON/)의 **실제 AWS 적용값 기록**과 과거 설계/부분 기록을 구분한다. 파일 번호가 낮다고 현재 적용 정책인 것은 아니다. [2026-11-12 정책 대조표](JSON/AWS_정책_대조_2026-11-12.md) 참고.
2. 기존 계정 ID가 들어간 모든 IAM ARN, S3 버킷 ARN, 리소스 이름, 리전 조건, 호스팅 영역 ID, SES identity ARN, KMS 키 등을 새 환경 값으로 치환한다. 단순 문자열 일괄 치환 뒤 **사람이 각 정책을 다시 검토**한다.
3. IAM 정책은 사용자/역할에 연결한 뒤에도 실제 허용·거부 시험이 필요하다. `Resource: "*"`나 태그 기반 조건은 의도치 않은 범위를 허용할 수 있으므로 최소 권한 재검토한다.
4. 권한 생성·연결 시점, 정책 버전, 실제 시험 결과를 구분하여 기록한다. AWS 정책 변경과 GitHub JSON 커밋은 별개 작업이다.
5. 실제 계정 ID·리소스 식별자 등은 인계에 필요한 범위에서만 사용하고, **액세스 키·비밀번호·세션 토큰·메일 인증 정보는 GitHub에 기록하지 않는다.**

## 4. Web EC2 전용 역할 재구성 주의

- 새 Web 역할 `haven-ec2-web-role`에는 `AmazonSSMManagedInstanceCore`, `/haven/*` Parameter Store 읽기, SES 발송, `/haven/web` CloudWatch Logs 쓰기, S3 `db-backups/*`에 `s3:GetObject`·`s3:PutObject`가 필요하다고 기존 구성에서 확인했다.
- 역할과 **같은 이름의 인스턴스 프로파일** 존재를 확인하고, `web-1`에 연결하기 전 `iam:PassRole` 허용 범위와 `ec2:ReplaceIamInstanceProfileAssociation`·`ec2:DescribeIamInstanceProfileAssociations`를 검토한다.
- 기존 공통 역할 `haven-ec2-ssm-role`은 DB와 롤백을 위해 보존한다. **Web 역할을 만들었다고 EC2 연결이 자동으로 바뀌지는 않는다.** 실제 연결·재시작·SSM·백업·로그·SES 검증은 민성 담당.
- 11/13 기존 계정의 교체 정책은 서울 리전 `Resource: "*"`이므로 **새 계정에 그대로 이식하지 말고 대상 범위를 재검토**한다.

## 5. 데이터·도메인·비용 안전 확인

- 새 계정에서 백업 복원 시 운영 DB/업로드 경로를 덮어쓰지 않고 **격리된 DB/디렉터리**에서 먼저 검증한다. 11/13 기존 계정 시험은 DB 13 tables, 업로드 7개 SHA-256 일치로 민성이 보고했으며 새 계정에서도 재시험해야 한다.
- Route 53 호스팅 영역을 새로 만들면 네임서버·도메인 등록업체 위임·ACM/SES 검증 레코드가 달라질 수 있다. 조장 승인 전 기존 서비스 DNS를 전환하지 않는다.
- ALB·NAT·공인 IPv4·EBS·WAF·CloudWatch·Route 53·S3는 서비스가 꺼져 있어도 일부 비용이 발생할 수 있다. 새 계정에서 별도 비용표와 경보를 확인한다.
- [기존 계정 종료 확인 목록](AWS_자원현황_종료확인목록_2026-11-11.md)은 **자원 식별 참고 자료**일 뿐 새 계정에 같은 자원이 존재한다는 증거가 아니다.
