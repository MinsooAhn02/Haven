공인 IPv4 세 개는 확인 당시 모두 연결 ID가 있었음. **연결됨은 무료라는 뜻이 아님.** 실제 과금 여부/금액은 Cost Explorer나 청구서에서 별도 확인.

### SES/DNS 교차 확인

- Route 53에서 **SES Easy DKIM CNAME 3개가 존재하는 것**을 확인. 같은 호스팅 영역에 A·NS·SOA·ACM 인증용 CNAME도 조회됨.
- SES 자격 증명 목록은 조회 시 `orchestration-haven.cloud` **확인 보류 중**. DNS 생성과 SES 인증 성공은 별개의 상태임.
- [SES DKIM DNS 인계 PR #58](https://github.com/MinsooAhn02/Haven/pull/58) 참고.

## 2. 기존 설계/구축 기록에는 있으나 현재 콘솔 화면으로 별도 개수 확인하지 않은 자원

| 항목 | 현재 문서로 아는 내용 | 이번 확인 상태 |
|---|---|---|
| 인터넷 게이트웨이(IGW), 라우팅 테이블 | 민성 네트워크 구축/운영 결정 문서에 구성 기록 | **별도 개수·연결 상태 미확인** |
| S3 Gateway Endpoint | 민성 구축 및 AWS 운영 결정에 사용 기록 | **현재 자원 존재/개수 미확인** |
| ACM HTTPS 인증서 | 민성 ALB·HTTPS 배포 성공 기록 | **인증서 목록·만료일 미확인** |
| ALB 대상 그룹·리스너 | 민성 `build-alb.sh` 구성 기록 | **현재 목록·개수 미확인** |
| EBS 스냅샷 | 볼륨 화면에 스냅샷 ID 일부 표시 | **현재 스냅샷 목록/실제 보존 수량 미확인** |
| CloudWatch Logs/로그 그룹 | 운영 계획 및 보안 담당 범위 | **현재 개수·보존 정책 미확인** |
| IAM 사용자·역할·정책 | 보람 IAM 정책 파일 및 실제 설정 기록 | **전체 자원 수량·미사용 자격 증명 미확인** |
| 다른 AWS 리전 자원 | 서울 리전 집중 운영 | **타 리전 미확인** |
| S3 버킷 내부 백업 파일·버전 | 백업 버킷 자체는 확인 | **실제 백업/복원·객체 수량 미확인** |

위 미확인 항목을 임의로 '없음' 또는 '완료'로 기록하지 않음. 기존 자료로 정리할 수 있는 부분은 반영했고, **보람에게 동일 화면 재캡처를 요청할 필요 없음**. 실제 종료·보존 결정을 할 때 해당 자원 담당자가 현 상태를 재검토.

## 3. 종료 확인 및 담당자 인계 (실행하지 않음)

| 범위 | 담당 | 확인할 사항 |
|---|---|---|
| 서버, VPC, 서브넷, SG, NAT/EIP, ALB, IGW·라우트·Endpoint | **민성** | 현재 구성, 연결 의존성, 재구성 방법, 운영 종료 후 대상 확정 |
| 백업·EBS·스냅샷·S3 객체 | **민성(백업 실행) + 보람(비용·버킷 현황)** | 백업/복구 시험 및 보존 필요성 먼저 확인 |
| DNS·ACM·도메인 | **민성** | 실제 서비스 접근, 인증서·DNS·갱신/보존 여부 |
| WAF·로그 | **혁민** | 보안 점검 결과·로그 증빙 및 보존 기간 |
| IAM·SES·비용 | **보람** | 사용자/정책 접근, SES 인증 상태, 크레딧·청구서 실사용액, 자원 목록 업데이트 |
| 최종 변경 승인 | **조장 민성** | 종료·보존 대상의 승인 및 담당자 실행 조정 |

**주의:** 해당 목록은 *종료 시 검토 대상*이지 *현재 삭제 지시 목록*이 아닙니다. 자원 삭제·백업 삭제·DNS 변경은 수행하지 않았으며, 종료 전 조장 결정과 담당자별 재확인이 필요합니다.
