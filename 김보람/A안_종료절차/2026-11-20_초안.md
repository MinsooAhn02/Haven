## 1. 임시 부여할 IAM 권한과 적용 범위 (a)

### 확인된 스크립트 기준

민성님의 `이민성/infra/destroy.sh`에는 다음 9종류를 찾고 삭제하는 단계가 있다.

| 삭제 후보 | 스크립트에 사용된 대표 AWS 명령(권한 후보) |
|---|---|
| EC2 | `ec2:TerminateInstances` |
| NAT Gateway | `ec2:DeleteNatGateway` |
| EIP | `ec2:ReleaseAddress` |
| S3 Gateway Endpoint | `ec2:DeleteVpcEndpoints` |
| 보안 그룹(SG) | `ec2:RevokeSecurityGroupIngress`, `ec2:RevokeSecurityGroupEgress`, `ec2:DeleteSecurityGroup` |
| 라우팅 테이블 | `ec2:DisassociateRouteTable`, `ec2:DeleteRouteTable` |
| 서브넷 | `ec2:DeleteSubnet` |
| 인터넷 게이트웨이(IGW) | `ec2:DetachInternetGateway`, `ec2:DeleteInternetGateway` |
| VPC | `ec2:DeleteVpc` |

스크립트의 대상 조회·상태 확인에 쓰는 `ec2:Describe*` 읽기 권한도 필요할 수 있다. 최종 권한 목록은 **민성님이 확정한 삭제 명령과 현재 IAM 권한을 대조한 뒤 부족한 것만** 추가한다. 위 표는 부여 확정 목록이 아니다.

### 제한 조건 / 미확정 사항

- **서울 리전:** `ap-northeast-2`로 제한하는 방향. 실제 IAM 정책의 `aws:RequestedRegion` 등 적용 가능 여부는 권한별 확인 후 확정한다.
- **대상 태그:** 현재 스크립트는 `Project=Haven`, `Owner=minsung` 태그로 자원을 *조회*한다. **조회 필터만으로 IAM 삭제 권한까지 제한되는 것은 아니다.** 각 삭제 API가 태그·리소스 범위 조건을 지원하는지 확인해 가능한 범위에서 제한한다.
- **추가 자원:** 현재 `destroy.sh`에는 ALB·WAF 삭제 단계가 없다. 이 밖의 자원(S3 백업, 로그, SES 등) 포함 여부와 담당자도 별도로 확정한다.
- **미확정:** 최종 삭제 대상 목록, 민성님의 기존 권한으로 가능한 작업, 추가할 정책 Action/Resource/Condition, 태그 조건 지원 여부, 조장의 최종 실행 승인.
- **금지 원칙:** 계정 전체 관리자 권한을 임시로 부여하지 않고, 종료 대상 외 자원과 서울 외 리전으로 범위를 넓히지 않는다. 예외가 필요하면 이유·대상·기간을 먼저 승인받는다.

## 2. 권한 부여·회수 시점 및 확인 방법 (b)

1. **종료 전:** 조장에게 삭제 대상·보존 대상·실행 날짜를 최종 승인받고, 민성님이 실제 종료 순서와 스크립트를 확정한다. 백업·필요 로그 보존 여부를 먼저 확인한다.
2. **임시 부여 직전:** 민성 IAM 사용자에 연결된 정책과 권한 상태를 기록한다. 확정된 대상에 **현재 없는 최소 권한만** 별도의 임시 정책으로 부여할 계획이다.
3. **부여 시점:** 승인된 종료 작업 **시작 직전**. 정책 연결 및 적용 범위를 확인한다. 실제 부여는 종료 승인 전에는 하지 않는다.
4. **실행 확인:** 민성님이 삭제 목록을 검토하고 조장 승인 후 실행한다. `destroy.sh`의 일반 실행은 삭제 목록 출력, `DRY_RUN=1`은 **가짜 ID로 명령 순서만 미리 보기**이므로 실제 자원·권한 검증으로 간주하지 않는다.
5. **회수 시점:** 승인된 종료 작업이 끝난 **즉시**, 실패나 중단으로 작업을 멈춘 경우에도 임시 권한 회수 여부를 먼저 판단한다. 재실행이 필요하면 다시 승인받는다.
6. **회수 확인:** IAM 사용자 `minsung`의 정책 연결 목록에서 임시 정책이 제거되었는지 확인하고 기록한다. 남은 접근 경로·유효 세션 여부도 확인해 추가 삭제 권한이 남지 않았는지 점검한다.

## 3. 권한 회수 후 IAM 정책 재대조 (c)

1. **부여 전 기준 기록**과 회수 후 민성님의 IAM 정책 연결 목록을 비교해 임시 정책이 남지 않았는지 확인한다.
2. 기존 IAM 정책의 AWS 저장 내용과 GitHub `김보람/JSON/` 정책 파일을 대조한다. 계정 번호 마스킹 같은 표기 차이와 실제 권한 차이는 구분한다.
3. 정책 연결뿐 아니라 사용자 인라인 정책·그룹·역할 등 **다른 경로로 임시 삭제 권한이 남아 있지 않은지** 확인한다. 실제 자원 삭제로 권한을 시험하지 않는다.
4. 비교 결과를 날짜·담당자·정책 이름·이상 여부로 기록한다. 불일치가 있으면 임의 수정하지 않고 조장에게 보고 후 승인받아 처리한다.
