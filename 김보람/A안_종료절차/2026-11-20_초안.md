### 1. 이민성 — 인프라 종료

| 대상 | 권한 | 확인 근거 |
|---|---|---|
| NAT Gateway | `ec2:DeleteNatGateway` | 12번 기존 정책 |
| EIP 해제 | `ec2:ReleaseAddress` | 12번 기존 정책 |
| ALB·리스너·대상 그룹 | `elasticloadbalancing:DeleteLoadBalancer`, `elasticloadbalancing:DeleteListener`, `elasticloadbalancing:DeleteTargetGroup` | 18번 기존 정책 |

위 권한은 **GitHub 파일에 포함된 것**이며, 실제 AWS 사용자 연결·태그 조건 충족·작동 여부는 확인 전이다.

**운영 자원 종료를 위해 추가 검토할 권한**

| 삭제·정리 대상 | 임시 권한 후보 | 기존 권한의 제한 또는 확인 사유 |
|---|---|---|
| 운영 EC2 | `ec2:TerminateInstances` | 13·34번은 시험용 인스턴스 이름에 제한 |
| 운영 보안 그룹 | `ec2:DeleteSecurityGroup` | 15·34번은 시험용 SG에 제한 |
| SG 인바운드 규칙 | `ec2:RevokeSecurityGroupIngress` | 12번은 특정 default SG만 허용 |
| VPC Endpoint | `ec2:DeleteVpcEndpoints` | 기존 대조 정책에서 미확인 |
| 라우팅 테이블 | `ec2:DisassociateRouteTable`, `ec2:DeleteRouteTable` | 기존 대조 정책에서 미확인 |
| 서브넷 | `ec2:DeleteSubnet` | 기존 대조 정책에서 미확인 |
| 인터넷 게이트웨이 | `ec2:DetachInternetGateway`, `ec2:DeleteInternetGateway` | 기존 대조 정책에서 미확인 |
| VPC | `ec2:DeleteVpc` | 기존 대조 정책에서 미확인 |

민성님의 `이민성/infra/destroy.sh`에는 EC2·NAT·EIP·VPC Endpoint·SG·라우팅 테이블·서브넷·IGW·VPC의 종료 단계가 있다. 대상 조회에는 EC2 `Describe*` 권한도 사용하며, 12번 정책에 해당 조회 권한이 포함되어 있다. **ALB·WAF 삭제 단계는 현재 스크립트에 없으므로** 최종 종료 순서와 담당자를 별도로 확인한다. EBS 볼륨 등을 별도로 삭제하기로 결정할 경우 해당 권한을 추가 대조한다.

### 2. 권혁민 — WAF 종료

| 작업 | 권한 | 검토 결과 |
|---|---|---|
| WAF–ALB 연결 해제 | `wafv2:DisassociateWebACL` | **민성 담당 확정.** 26번 기존 권한 사용, 혁민에게 임시 부여하지 않음 |
| WAF Web ACL 삭제 | `wafv2:DeleteWebACL` | **혁민 담당 확정.** 25번 기존 권한 사용, 임시 부여 불필요 |

**조장 11/20 결정:** 혁민에게 임시로 부여할 권한은 위 로그 정리 권한 **2개만**이다. 대상은 서울 리전의 `haven-web-acl` Web ACL ARN과 `aws-waf-logs-haven` 로그 그룹 ARN으로 각각 제한한다. **로그 그룹 삭제는 12/11 필요한 로그 압축 보관 및 파일 확인이 완료된 뒤** 진행한다. 실제 권한 정책 연결·삭제 실행은 최종 종료 승인 전에는 하지 않는다.

### 3. 임시 권한의 적용 범위

| 항목 | 적용 원칙 |
|---|---|
| 리전 | 서울 `ap-northeast-2`로 제한 |
| 인프라 대상 | 승인된 Haven 자원. 가능하면 `Project=Haven`, `Owner=minsung` 태그 조건 유지 |
| WAF 로그 설정 제거 | 서울 리전의 `haven-web-acl` Web ACL ARN으로 제한 |
| WAF 로그 그룹 삭제 | 서울 리전의 `aws-waf-logs-haven` 로그 그룹 ARN으로 제한 |
| 권한 종류 | 기존 권한으로 가능한 작업은 중복 부여하지 않고, 부족한 삭제·연결 해제 작업만 임시 허용 |

`destroy.sh`의 태그 필터는 **삭제 대상 조회 조건**이지 IAM 권한 제한 자체는 아니다. IAM 정책에서 자원 ARN·리전·리소스 태그 조건을 각 API가 지원하는지 확인한 후 적용한다. 태그 조건이 지원되지 않으면 **승인된 리소스 ARN으로 제한 가능한지 우선 검토**하고, 범위 확대가 불가피한 경우 조장 승인 후 결정한다.

### 4. 최종 확인이 필요한 사항

1. 민성의 실제 삭제 대상이 현재 `destroy.sh`의 9종류와 일치하는지, 조장이 ALB·WAF 관련 스크립트 보완을 마쳤는지.
2. 운영 자원의 실제 태그 및 민성 IAM 사용자에 연결된 기존 정책과 권한 적용 상태.
3. 혁민의 실제 IAM 정책 연결 상태와 `haven-web-acl`·`aws-waf-logs-haven` ARN 범위 적용 가능 여부, 12/11 로그 압축 보관 완료 여부.
4. 각 추가 권한에 적용 가능한 서울 리전·자원 ARN·태그 제한 조건과 실제 부여 목록.

**조장 11/20 종료 순서 제안:** 유지·삭제 여부를 팀에서 확정하고 **삭제 승인 시에만** 민성 WAF–ALB 연결 해제 및 ALB 정리 → 혁민 Web ACL 삭제 → **12/11 로그 압축 보관·파일 확인 후** 혁민 로그 설정·그룹 정리 → 민성 `destroy.sh` 9종류 정리 순으로 검토한다. ALB·WAF 단계의 스크립트 보완은 조장 담당이며, 상세 부여·회수 시점은 (b)에 정리한다. **12/02 발표 직후 자동 삭제가 아니라, 심화 프로젝트 재사용 여부를 확인한 뒤 유지 또는 삭제를 결정한다.**

**판단:** 민성의 인프라 삭제 권한은 **추가 검토 후보**이며, 혁민의 WAF 로그 정리 임시 권한 2개는 조장 결정에 따라 범위를 정리했다. 실제 IAM 정책 연결·자원 삭제는 승인된 종료 시점까지 하지 않는다.

## (b) 권한 부여·회수 시점 및 확인 방법

### 1. 권한 부여 전 확인

- Haven은 심화 프로젝트(2027년 1월 11일 최종발표)에서도 이어서 사용할 예정이므로, 12월 2일 최종발표 후 AWS 자원을 바로 삭제하지 않는다.
- 심화 프로젝트에 필요한 자원은 유지하며, 이후 팀에서 실제 종료 대상과 일정을 확정한 경우에만 삭제에 필요한 IAM 권한을 임시 부여한다.
- 자원 삭제에 대한 팀 승인을 확인한다.
- 승인된 삭제 대상과 (a)에 정리한 임시 권한 목록을 대조한다.
- 권한 범위는 서울 리전 및 승인된 Haven 자원으로 제한한다.

### 2. 임시 권한 부여 시점

**① 이민성 — 인프라 삭제 권한**

- 팀에서 인프라 삭제 대상과 일정을 최종 승인한 후 진행한다.
- 민성님이 `destroy.sh` 실행 준비를 완료하고 삭제 작업을 시작하기 **직전에** 필요한 IAM 권한을 임시 부여한다.
- 기존 권한으로 수행할 수 있는 작업에는 추가 권한을 부여하지 않는다.

**② 권혁민 — WAF 로그 정리 권한**

- 민성님이 WAF–ALB 연결을 해제한 후, 혁민님이 기존 권한으로 Web ACL 삭제를 먼저 시도한다.
- Web ACL 삭제가 실패하고 로그 설정 삭제가 필요한 경우, 팀 승인 후 작업 직전에 `wafv2:DeleteLoggingConfiguration` 권한만 임시 부여한다. 로그 설정을 삭제한 뒤 Web ACL 삭제를 재시도한다.
- 로그 그룹 삭제는 12월 11일 예정된 로그 압축 보관과 파일 확인이 완료되고 별도로 승인된 경우에만, 작업 직전에 `logs:DeleteLogGroup` 권한을 임시 부여한다.
- 두 임시 권한은 필요한 작업에 각각 부여하고, 작업 완료 또는 취소 시 회수한다.
- 권한 대상은 승인된 `haven-web-acl`과 `aws-waf-logs-haven` ARN으로 제한한다.
- 12월 11일은 로그 압축 보관 예정일이며, 권한 부여일이나 로그 삭제일로 확정하지 않는다.

### 3. 권한 부여 확인 방법

- AWS IAM에서 대상 사용자 또는 역할에 임시 정책이 정상적으로 연결되었는지 확인한다.
- 정책의 허용 작업, 대상 자원, 리전 및 적용 가능한 제한 조건을 확인한다.
- 권한 부여 시각과 정책 이름을 기록한다.
- 실제 자원 삭제 시험은 진행하지 않는다.

### 4. 권한 회수 시점 및 확인 방법

- **민성님:** 승인된 인프라 삭제 작업 완료를 확인하면 임시 권한을 즉시 회수한다.
- **혁민님:** 승인된 WAF 로그 정리 작업 완료를 확인하면 임시 권한을 즉시 회수한다.
- 작업이 취소되거나 중단된 경우에도 임시 권한을 회수하며, 작업 재개 시에는 다시 승인을 확인한다.
- AWS IAM에서 임시 정책이 정상적으로 분리되었는지 확인한다.
- 기존에 사용하던 상시 권한은 임시 권한과 구분하여 유지한다.
- 권한 회수 시각과 확인 결과를 기록한다.

### 5. 종료 작업 순서

조장님이 제안한 순서를 기준으로 하며, 실제 실행은 팀의 최종 승인 후 진행한다.

1. 12월 2일 최종발표·재시연 이후 심화 프로젝트에서 사용할 자원을 확인하고, 팀에서 유지·삭제 여부 및 일정을 결정한다.
2. 삭제 승인 시 민성님이 기존 권한으로 WAF–ALB 연결 해제 및 ALB·리스너·대상 그룹을 정리한다.
3. 혁민님이 기존 권한으로 WAF Web ACL 삭제를 먼저 시도한다. 실패하여 로그 설정 삭제가 필요한 경우에만 승인 후 임시 권한을 부여해 로그 설정을 삭제하고, Web ACL 삭제를 재시도한다.

5. 승인된 종료 일정에 맞춰 민성님에게 필요한 임시 권한을 부여하고 `destroy.sh` 대상 자원 9종류를 정리한다.
6. 각 담당자의 작업 완료 또는 취소를 확인한 뒤 보람이가 해당 임시 권한을 즉시 회수하고, 회수 여부를 확인한다.

**현재 상태:** 권한 부여·회수 절차 작성 단계이며, 실제 IAM 임시 권한 부여·회수 및 AWS 자원 삭제는 진행하지 않음.
