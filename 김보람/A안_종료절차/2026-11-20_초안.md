## (a) 임시 권한 목록 및 범위

### 1. 이민성 — 인프라 종료

**기존 GitHub IAM JSON에 포함된 권한**

| 대상 | 권한 | 확인 근거 |
|---|---|---|
| NAT Gateway | `ec2:DeleteNatGateway` | 12번 기존 정책 |
| EIP 해제 | `ec2:ReleaseAddress` | 12번 기존 정책 |
| ALB·리스너·대상 그룹 | `elasticloadbalancing:DeleteLoadBalancer`, `elasticloadbalancing:DeleteListener`, `elasticloadbalancing:DeleteTargetGroup` | 18번 기존 정책 |
| SG 아웃바운드 규칙 | `ec2:RevokeSecurityGroupEgress` | 12번 기존 정책 |

위 권한은 **GitHub 파일에 포함된 것**이며, 실제 AWS 사용자 연결·태그 조건 충족·작동 여부는 확인 전이다.

**운영 자원 종료를 위해 추가 검토할 권한**

| 삭제·정리 대상 | 임시 권한 후보 | 기존 권한의 제한 또는 확인 사유 |
|---|---|---|
| 운영 EC2 | `ec2:TerminateInstances` | 13·34번은 시험용 인스턴스 이름에 제한 |
| 운영 보안 그룹 | `ec2:DeleteSecurityGroup` | 15·34번은 시험용 SG에 제한 |
| SG 인바운드 규칙 | `ec2:RevokeSecurityGroupIngress` | 12번은 특정 default SG만 허용 |
| VPC Endpoint | `ec2:DeleteVpcEndpoints` | 기존 대조 정책에서 미확인 |
| 라우팅 테이블 | `ec2:DisassociateRouteTable`, `ec2:DeleteRouteTable` | 기존 대조 정책에서 미확인 |
| 서브넷 | `ec2:DeleteSubnet` | 기존 대조 정책에서 미확인 |
| 인터넷 게이트웨이 | `ec2:DetachInternetGateway`, `ec2:DeleteInternetGateway` | 기존 대조 정책에서 미확인 |
| VPC | `ec2:DeleteVpc` | 기존 대조 정책에서 미확인 |

민성님의 `이민성/infra/destroy.sh`에는 EC2·NAT·EIP·VPC Endpoint·SG·라우팅 테이블·서브넷·IGW·VPC의 종료 단계가 있다. 대상 조회에는 EC2 `Describe*` 권한도 사용하며, 12번 정책에 해당 조회 권한이 포함되어 있다. **ALB·WAF 삭제 단계는 현재 스크립트에 없으므로** 최종 종료 순서와 담당자를 별도로 확인한다. EBS 볼륨 등을 별도로 삭제하기로 결정할 경우 해당 권한을 추가 대조한다.

### 2. 권혁민 — WAF 종료

| 작업 | 권한 | 검토 결과 |
|---|---|---|
| WAF Web ACL 삭제 | `wafv2:DeleteWebACL` | 25번 기존 JSON에 포함 |
| WAF와 ALB 연결 해제 | `wafv2:DisassociateWebACL` 등 | 민성 26번에 관련 권한이 있음. 혁민에게 직접 부여할지는 담당 분담 확인 |
| WAF 로그 설정 제거 | `wafv2:DeleteLoggingConfiguration` | 추가 검토 후보 |
| WAF 로그 그룹 삭제 | `logs:DeleteLogGroup` | 추가 검토 후보 |

조장 11/20 댓글에 따라 WAF Web ACL·WAF 로그 정리는 **혁민 담당**이다. 연결 해제는 **민성의 선행 작업으로 할지, 혁민에게 임시 권한을 줄지 확인 대기**이다. 로그는 필요한 기록의 보관 완료를 확인한 뒤 정리한다.

### 3. 임시 권한의 적용 범위

| 항목 | 적용 원칙 |
|---|---|
| 리전 | 서울 `ap-northeast-2`로 제한 |
| 인프라 대상 | 승인된 Haven 자원. 가능하면 `Project=Haven`, `Owner=minsung` 태그 조건 유지 |
| WAF | 서울 리전의 `haven-web-acl` 등 승인된 Web ACL ARN으로 범위 제한 |
| WAF 로그 | `aws-waf-logs-haven` 등 승인된 로그 그룹 ARN으로 범위 제한 |
| 권한 종류 | 기존 권한으로 가능한 작업은 중복 부여하지 않고, 부족한 삭제·연결 해제 작업만 임시 허용 |

`destroy.sh`의 태그 필터는 **삭제 대상 조회 조건**이지 IAM 권한 제한 자체는 아니다. IAM 정책에서 자원 ARN·리전·리소스 태그 조건을 각 API가 지원하는지 확인한 후 적용한다. 태그 조건이 지원되지 않으면 **승인된 리소스 ARN으로 제한 가능한지 우선 검토**하고, 범위 확대가 불가피한 경우 조장 승인 후 결정한다.

### 4. 최종 확인이 필요한 사항

1. 민성의 실제 삭제 대상이 현재 `destroy.sh`의 9종류와 일치하는지, ALB 및 기타 자원 종료 순서는 어떻게 되는지.
2. 운영 자원의 실제 태그 및 민성 IAM 사용자에 연결된 기존 정책과 권한 적용 상태.
3. 혁민의 WAF–ALB 연결 해제 담당과 WAF 로그 정리 순서, 현재 연결 정책 상태.
4. 각 추가 권한에 적용 가능한 서울 리전·자원 ARN·태그 제한 조건과 실제 부여 목록.

**판단:** 위 표는 **권한 후보를 정리한 검토안**이다. 실제 임시 정책 생성·연결·자원 삭제는 승인된 종료 시점까지 하지 않는다.
