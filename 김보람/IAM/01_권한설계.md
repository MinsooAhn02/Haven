
# Haven 프로젝트 IAM 권한 설계 (1차 초안)

## 1. 작업 목적
AWS 팀 프로젝트에서 담당자별 필요한 권한만 부여하고, 승인되지 않은 작업은 제한하여 안전하게 운영한다.

## 2. 팀원별 IAM 권한

| 담당자 | 필요한 권한 |
|---|---|
| 이민성 | VPC, EC2, 보안그룹, NAT, ALB 구축 및 관리 |
| 안민수 | Web·DB 서버 SSM 접속, 배포 및 승인된 백업·복원 |
| 권혁민 | 보안그룹·로그·WAF 조회 및 승인된 보안 시험 |
| 김보람 | IAM 사용자·Role 관리 및 예산·비용 조회 |
| 신요찬 | 현재 AWS 콘솔 권한 불필요 |
| 노푸른 | 현재 AWS 콘솔 권한 불필요 |

모든 권한은 담당 업무에 필요한 최소 범위로 제한하며, MFA 사용을 원칙으로 한다.

## 3. EC2 서버 Role 설계

| 서버 | Role 이름(제안) | 필요한 권한 |
|---|---|---|
| Web | Haven-Web-EC2-Role | SSM 접속 지원, 로그 전송 |
| DB | Haven-DB-EC2-Role | SSM 접속 지원, 로그 전송, 지정된 S3 경로에 백업 저장 |

- 공통 SSM 정책: `AmazonSSMManagedInstanceCore`
- 로그 전송: 지정된 CloudWatch Logs 대상만 허용
- S3 백업: 지정된 버킷·경로만 허용하며 임의 삭제는 제한
- 실제 Role 이름과 정책 범위는 이민성님의 구축 스크립트와 대조 후 확정

## 4. 이민성 담당자 권한

- 승인된 네트워크 및 EC2 자원 생성·관리
- `iam:PassRole`은 승인된 Web·DB 서버 Role에만 허용
- 승인되지 않은 IAM Role 전달 및 IAM 관리자 권한 부여 제한

## 5. 허용·거부 시험 계획

- 승인된 운영자 → 지정 서버 SSM 접속 성공
- 일반 계정 → SSM 접속 거부
- EC2 → 필요한 로그 전송 성공
- DB 서버 → 지정된 S3 백업 경로 쓰기 성공
- DB 서버 → 다른 S3 버킷 및 허가되지 않은 작업 거부
- 이민성 → 승인되지 않은 Role 전달 거부


## 6. IAM 작업 계획 및 완료 기준

**완료 목표: 2026년 11월 11일(수) 서버 구축 전까지**

- 팀원별 담당 업무에 맞는 IAM 정책 JSON 작성
- Web·DB 서버용 IAM Role 및 정책 JSON 작성
- 이민성 담당자의 `iam:PassRole` 권한 범위 설정
- SSM 접속 허용·거부 대상 구분
- CloudWatch 로그 전송 및 S3 백업 권한 설정
- 이민성 담당자와 Role 이름 및 권한 범위 확인
- 확정된 IAM 권한을 AWS에 적용하고 가능한 허용·거부 시험 진행
- 적용 결과와 미검증 항목을 기록하여 이민성 담당자에게 전달

**완료 기준:** 서버 구축에 필요한 IAM 권한을 적용하고, 서버 생성 전에 검증 가능한 항목을 확인한다. 실제 서버가 필요한 SSM 접속 및 로그·백업 시험은 서버 구축 후 진행한다.

**현재 상태: 설계 초안 / 실제 AWS 권한 적용 전**

계정 ID와 자원 ARN은 추후 계정 이전이 가능하도록 변수로 관리한다.
