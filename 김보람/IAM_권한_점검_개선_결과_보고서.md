# IAM 권한 점검·개선 결과 보고서

- 프로젝트: Haven
- 구분: 기본 2 도전(C2)
- 작성자: 김보람
- 작성일: 2026-11-27 / 점검 근거: 2026-11-26 결과 정리 및 1~4회차 작업 기록

## 1. 점검 목적 및 방법

팀원별 업무에 필요한 AWS 권한이 정상 동작하는지, 불필요하거나 과도한 권한이 포함되어 있는지 확인하였다. 업무상 필요한 접근이 거부되면 원인을 확인하여 필요한 범위만 보완하였고, 불필요한 접근은 권한을 제거하거나 대상·리전·태그 조건으로 제한하였다.

점검 대상은 개인 IAM 사용자, Web·DB EC2 역할, 정책 JSON, SSM 관리 접속, 로그·백업·메일 접근이다. IAM 정책 시뮬레이터, 실제 작업/담당자 보고, AWS 정책 연결·JSON 조회, GitHub 저장본 대조를 이용하였다. 시뮬레이션·정책 확인·실제 실행은 서로 다른 확인 방법이며, 기록이 없는 항목은 성공 또는 실패로 단정하지 않는다.

## 5. AWS 정책과 GitHub JSON 대조

11/20 정책 저장본 대조에서 확인한 정책은 05·16·17·18·19·21·22·23·26·29·30·35번이다. 확인된 권한 내용은 일치하였으며 계정 번호·호스팅 영역 ID 등 가림 표기는 구분하였다. 26번은 제공받은 AWS 정책 JSON과 GitHub 수정본 대조이며 실제 AWS 저장 후 재조회·Block 전환 재시험은 별도 증빙이 필요한 범위이다.

11/20에는 07·11·14번 연결과 AWS 저장본도 확인하였다. 11/23 후속 확인으로 17번 실제 Hosted Zone ID 일치와 22번 DB 역할에서 Web 로그 정책이 제거된 상태를 재확인하였다. DB 역할의 실제 거부 시험까지 실시한 것은 아니다.

## 7. 권한 회수 후 재대조 계획

종료 승인 후 임시 삭제 권한이 필요할 경우 민성(인프라), 혁민(WAF·로그)의 기존 정책을 기록하고 필요한 대상에만 권한을 추가한다. 종료 작업 뒤 임시 정책을 회수하며 기존 정책 JSON, Action/Resource/Condition, 그룹·역할의 다른 권한 경로를 대조한다. 정책 시뮬레이터 등 실제 삭제를 일으키지 않는 방법으로 추가 권한이 제거되었는지 검증하고 결과와 시각을 기록한다. 현재는 절차를 준비한 단계로 실제 부여·회수·재대조는 미실행이다.

## 8. 종합 결과

업무에 필요한 권한을 보완하면서, QA 읽기 권한 축소, 시험용 삭제 제한, Web/DB 역할 분리 및 서버별 로그·메일 권한 구분으로 접근 통제를 개선하였다. 정책 일치 확인과 실제 정상 동작·거부 기록을 확보하였으며, 미확인 시험 및 잔여 위험은 별도로 관리한다. 모든 IAM 시험을 완료했다고 주장하지 않으며 실제 AWS 설정 변경은 이번 문서 작성 범위에 포함하지 않는다.
