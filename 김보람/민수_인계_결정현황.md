## 4. 출구(NAT·S3) 및 메일·SSM 결정

| 통신 목적 | 현재 검토 방향 | 확인이 필요한 입력 |
| --- | --- | --- |
| 비공개 Web/DB의 일반 인터넷·패키지 설치 | NAT Gateway 1개 제안 | 실제 업데이트/외부 호출 필요 대상·기간·허용 경로; NAT 운영 비용 |
| SSM(Session Manager) 서버 관리 | 현 설계는 NAT 경유 가능성을 가정 | SSM 사용 방식·필수 연결, NAT 중단 시 접속 영향; VPC 인터페이스 엔드포인트 대안은 비용 별도 비교 |
| S3 백업·파일 접근 | S3 Gateway Endpoint 1개 제안 | S3 실제 채택 여부·버킷/정책·라우트 테이블 연결·파일/요청 사용량 |
| 로그·모니터링 | CloudWatch/로그 전송 요구 확인 | 로그 전송 대상·보존/조회량·연결 경로 |
| 시험 메일 | SES API(443) 또는 SMTP(587) 등 아직 미선정 | 민수님: 실제 사용할 메일 방식; 민성님: 출구·DNS 조건; 보람: 비용/권한 |

- **S3 Gateway Endpoint는 일반 인터넷이나 SSM 연결을 대신하지 않는다.** 자체 사용료는 없더라도 S3 사용 비용은 발생할 수 있다.
- NAT를 중지하는 것이 아니라 통상 **삭제 후 재구축**을 검토하게 되므로, **EIP·라우팅·SSM/설치 영향**을 확인하고 사전 승인 후 조치한다.
- NAT 1개는 비용을 줄이는 제안이며 가용 영역 장애 시 단일 출구 장애 위험/데이터 전송 비용을 검토해야 한다. **운영안으로 미승인**이다.
- ALB는 웹 서비스/HTTPS 연결에 필요한 단계에서 생성·시험·정리하는 일정이 필요하다. 정확한 날짜는 **민성님 구축 일정과 민수님 배포/시연 일정**에 따라 정한다.
