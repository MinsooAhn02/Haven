NAT
&nbsp;
• NAT Gateway는 삭제해야 유지 비용이 멈춘다.
• NAT를 삭제하면 SSM 접속이나 프로그램 설치가 안 될 수 있다. 
• NAT를 다시 만들면 라우팅 설정과 SSM 연결을 다시 확인해야 한다.
&nbsp;
• NAT를 삭제해도 공인 IP가 남아 있으면 IP 비용은 계속 발생할 수 있다
• NAT Gateway를 삭제해도 EIP(고정 공인 IP)는 자동 반납되지 않고, 라우팅 경로도 자동으로 정리되지 않는다.
&nbsp;
• 다만 ALB(인터넷 사용자가 우리 홈페이지에 들어올 때)의 공인 IP는 NAT의 EIP와 달리 AWS가 관리
• ALB를 삭제하면 AWS가 해당 주소를 반환
&nbsp;
• NAT를 삭제해도 S3 Gateway Endpoint는 사용할 수 있음
• S3 전용 연결은 NAT와 별개이기 때문에, 설정과 권한이 정상이라면 NAT를 삭제해도 S3 백업 저장소에 접근할 수 있음
&nbsp;
• 최종 정리는 팀원들 의견 + 팀장 승인 후 진행
최종 시연과 외부 백업 및 복원 검증이 완료되면, 팀장 승인 후 각 담당자가 NAT Gateway와 남은 EIP 등 불필요한 자원을 정리한다.
&nbsp;
결론
서버 구축·시험이 이어지는 기간에는 NAT 유지
며칠간 사용하지 않는 기간에는 삭제 여부 검토
최종 시연과 백업이 끝나면 NAT 및 남은 공인 IP 정리
