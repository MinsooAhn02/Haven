# Haven 프로젝트 AWS 관리 주의사항

## 1. 비용 관련

NAT Gateway: 유지 요금과 데이터 처리 요금이 발생한다. 삭제하면 추가 NAT 요금은 멈추지만, 삭제 전 사용한 요금은 청구된다.

EIP(공인 IP): NAT를 삭제해도 자동 반납되지 않으므로 별도로 확인해야 한다.

EC2: 서버를 중지해도 EBS(저장 공간) 비용은 남을 수 있다.

ALB: 서버를 중지하더라도 ALB가 남아 있으면 비용이 발생한다.

S3·스냅샷: 서버를 삭제해도 백업 파일이 남으면 저장 비용이 발생할 수 있다.

WAF·CloudWatch: 보안 검사와 로그 수집·저장에도 비용이 발생할 수 있다.

예산 알림: 1달러 알림은 경고일 뿐, AWS 서비스가 자동 중지되는 것은 아니다.

크레딧: 남은 크레딧과 별개로 무료/유료 플랜 상태와 적용 조건을 확인해야 한다.

## 2. 보안 및 접속 관련

루트 계정과 비밀번호, AWS 접근 키는 팀원에게 공유하거나 GitHub에 올리지 않는다.

팀원에게는 담당 업무에 필요한 권한만 부여한다.

관리자 권한은 승인 없이 부여하지 않는다.

보안 그룹을 임의로 변경하거나 DB 서버를 외부에 공개하지 않는다.

현재 설계에서는 NAT 삭제 시 SSM 접속과 프로그램 설치가 안 될 수 있다.

NAT 재생성 시 라우팅 설정과 SSM 연결을 다시 확인해야 한다.

S3 Gateway Endpoint는 NAT와 별개로 사용할 수 있지만, 라우팅과 접근 권한을 확인해야 한다.

## 3. 자원 삭제 및 관리

자원을 생성할 때 담당자, 생성일, 삭제 예정일을 기록한다.

자원 삭제 전 다른 팀원이 사용 중인지 확인한다.

서버 삭제 전 필요한 자료를 백업하고 복원 여부를 확인한다.

NAT 삭제 시 EIP와 라우팅 설정을 함께 점검한다.

프로젝트 종료 후 EC2, EBS, NAT, ALB, EIP, S3, WAF, CloudWatch 등 남은 자원을 확인한다.

자원 생성과 삭제는 팀장 및 담당자와 협의 후 진행한다.

# NAT Gateway 비용 및 관리

## 1. NAT Gateway

- NAT Gateway는 삭제해야 유지 비용이 멈춘다.
- NAT를 삭제하면 SSM 접속이나 프로그램 설치가 안 될 수 있다.
- NAT를 다시 만들면 라우팅 설정과 SSM 연결을 다시 확인해야 한다.

## 2. 공인 IP 비용

- NAT를 삭제해도 공인 IP가 남아 있으면 IP 비용은 계속 발생할 수 있다.
- NAT Gateway를 삭제해도 EIP(고정 공인 IP)는 자동 반납되지 않고, 라우팅 경로도 자동으로 정리되지 않는다.

## 3. ALB

- ALB의 공인 IP는 NAT의 EIP와 달리 AWS가 관리한다.
- ALB를 삭제하면 AWS가 해당 주소를 반환한다.

## 4. S3 Gateway Endpoint

- NAT를 삭제해도 S3 Gateway Endpoint는 사용할 수 있다.
- S3 전용 연결은 NAT와 별개이므로 설정과 권한이 정상이라면 NAT를 삭제해도 S3 백업 저장소에 접근할 수 있다.

## 5. 최종 정리

- 최종 정리는 팀원들 의견과 팀장 승인 후 진행한다.
- 최종 시연과 외부 백업 및 복원 검증이 완료되면, 팀장 승인 후 각 담당자가 NAT Gateway와 남은 EIP 등 불필요한 자원을 정리한다.

## 결론

- 서버 구축·시험이 이어지는 기간에는 NAT 유지
- 며칠간 사용하지 않는 기간에는 삭제 여부 검토
- 최종 시연과 백업이 끝나면 NAT 및 남은 공인 IP 정리
