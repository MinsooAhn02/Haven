
# Haven 프로젝트 AWS 구축 및 관리 주의사항


## 1. NAT Gateway (서버의 인터넷 연결)

**비용:** 유지 시간, 데이터 처리량, 데이터 전송에 따라 요금이 발생한다. 삭제 후 추가 NAT 사용 요금은 멈추지만, 이전 사용 요금은 청구된다.

**주의사항:** 현재 설계에서는 NAT를 삭제하면 SSM 접속이나 인터넷을 통한 프로그램 설치가 안 될 수 있다.

**삭제 시:** EIP(공인 IP)는 자동 반납되지 않으며, 기존 라우팅 경로도 자동 정리되지 않는다. 재생성 시 라우팅 설정과 서버 접속을 다시 확인해야 한다.

## 2. EIP (고정 공인 IP)

**비용:** 사용 중이거나 사용하지 않는 EIP 모두 시간당 요금이 발생한다. 일반적인 공인 IPv4 주소 요금은 시간당 $0.005이다.

**주의사항:** NAT Gateway를 삭제하더라도 EIP가 AWS 계정에 남아 있을 수 있다.

**삭제 시:** 다른 자원에서 사용 중인지 확인하고, 필요하지 않다면 담당자 승인 후 별도로 반납한다.

## 3. EC2 (가상 서버)

**비용:** 서버 종류와 실행 시간에 따라 요금이 발생한다.

**주의사항:** 서버를 중지하면 일반적인 인스턴스 사용 요금은 멈추지만 EBS(저장 공간), 공인 IP 등 별도 비용은 남을 수 있다.

**구축 시:** 필요한 크기의 서버만 생성하고, 서울 리전과 서버 개수를 확인한다. 불필요하게 큰 서버를 선택하지 않는다.

**삭제 시:** 서버 중지와 삭제는 다르다. 삭제하면 복구하지 못할 수 있으므로 데이터 백업과 담당자 확인이 필요하다.

## 4. EBS 및 스냅샷 (서버 저장 공간과 백업)

**비용:** EBS는 서버가 중지되어도 저장 공간 비용이 발생한다. 스냅샷도 별도 저장 비용이 발생할 수 있다.

**주의사항:** 서버 삭제 시 EBS가 함께 삭제되는지는 설정에 따라 달라진다.

**백업 시:** 스냅샷을 반복 생성하면 사용량이 증가할 수 있다. 불필요한 백업을 정리하되 필요한 복구 자료는 보존한다.

**삭제 시:** 서버 데이터가 필요한지 먼저 확인하고, 백업 파일로 실제 복원할 수 있는지도 시험한다.

## 5. ALB (홈페이지 접속 연결)

**비용:** ALB 사용 시간, 처리량(LCU), 공인 IPv4 주소 등에 대한 요금이 발생한다.

**주의사항:** EC2 서버를 중지하거나 NAT를 삭제해도 ALB가 남아 있으면 비용이 계속 발생할 수 있다.

**구축 시:** ALB에서 Web 서버로 요청이 정상 전달되는지, 보안 그룹이 올바르게 연결되어 있는지 확인한다.

**삭제 시:** ALB를 삭제하면 AWS가 관리하는 해당 공인 IP는 반환된다. 단, 연결된 다른 자원과 설정도 별도로 점검해야 한다.

## 6. VPC·서브넷·라우팅 테이블 (네트워크 구성)

**비용:** 일반적인 VPC, 서브넷, 라우팅 테이블 자체는 추가 요금이 없지만 NAT, 공인 IP, 데이터 전송 등 연결된 서비스에서는 요금이 발생할 수 있다.

**주의사항:** 라우팅 설정을 잘못 변경하면 서버의 인터넷 연결이나 AWS 서비스 연결이 끊길 수 있다.

**구축 시:** 현재 설계에 맞게 공개 영역과 비공개 영역을 구분하고, 필요한 통신 경로만 설정한다.

**변경 시:** 기존 설정을 기록하고 담당자와 협의한다. 변경 후 서버 간 연결과 외부 접속을 재확인한다.

## 7. Security Group (보안 그룹)

**비용:** 일반적인 보안 그룹 자체에는 별도 사용 요금이 없다.

**주의사항:** 접속을 허용하는 범위를 잘못 지정하면 외부에서 서버에 접근하거나 정상 접속이 차단될 수 있다.

**구축 시:** ALB는 필요한 웹 접속만 허용하고, Web 서버는 ALB에서 오는 요청만 받도록 제한한다.

**DB 서버:** PostgreSQL의 5432 포트는 승인된 Web 서버에서만 접근하도록 설정한다. 인터넷 전체에 공개하지 않는다.

**변경 시:** 테스트를 위해 임시 허용한 규칙은 종료 후 원래대로 복구한다.

## 8. SSM (서버 관리 접속)

**용도:** 서버의 SSH 포트를 인터넷에 공개하지 않고 관리하는 데 사용한다.

**주의사항:** SSM 접속을 위해 서버의 IAM Role(역할), SSM Agent, AWS 서비스 연결 상태가 정상이어야 한다.

**현재 설계:** SSM이 NAT를 통해 연결되므로 NAT 삭제 시 접속이 끊길 수 있다.

**확인사항:** 서버 구축 후 SSM 접속 성공 여부를 시험하고, NAT 및 라우팅 변경 후에도 재확인한다.

## 9. S3 및 S3 Gateway Endpoint (파일·백업 저장)

**비용:** S3는 저장 용량, 요청, 데이터 전송 등에 따라 요금이 발생한다. S3 Gateway Endpoint 자체에는 추가 사용 요금이 없다.

**주의사항:** S3 버킷을 실수로 공개하면 백업 파일이나 내부 자료가 외부에 노출될 수 있다.

**구축 시:** 공개 접근 차단과 필요한 IAM 권한을 확인한다. 백업 파일을 저장할 버킷과 경로도 정한다.

**NAT와의 관계:** Gateway Endpoint는 NAT와 별개로 동작한다. 올바르게 설정하면 NAT 없이도 S3에 접근할 수 있지만, SSM이나 일반 인터넷 접속까지 제공하는 것은 아니다.

**삭제 시:** S3에 남은 백업 파일은 별도로 확인한다. 버킷을 삭제하기 전 보관할 자료가 있는지 확인한다.

## 10. WAF (웹 방화벽)

**비용:** 웹 ACL, 규칙, 검사 요청 수 등에 따라 요금이 발생한다. 일부 고급 규칙과 기능에는 추가 비용이 발생할 수 있다.

**주의사항:** 규칙을 잘못 설정하면 정상적인 홈페이지 접속까지 차단할 수 있다.

**구축 시:** 처음에는 Count(탐지만 하고 차단하지 않는 방식)로 검사 결과를 확인한 후, 필요한 규칙을 Block(차단)으로 변경하는 방안을 검토한다.

**확인사항:** 차단된 요청과 정상 요청을 비교하고, 보안 시험 종료 후 규칙 상태를 기록한다.

## 11. CloudWatch (로그·모니터링)

**비용:** 로그 수집량, 저장량, 조회 및 알람 설정 등에 따라 비용이 발생할 수 있다.

**주의사항:** 로그 보관 기간을 설정하지 않으면 기본적으로 계속 보관되어 저장 비용이 늘어날 수 있다.

**구축 시:** 필요한 로그만 수집하고, 보관 기간과 예상 저장량을 정한다.

**확인사항:** 대량의 반복 요청을 사용하는 보안 시험에서는 로그가 급증할 수 있으므로 비용을 함께 점검한다.

## 12. CloudTrail (AWS 작업 기록)

**용도:** 누가 AWS 자원을 생성·수정·삭제했는지 확인하는 데 사용한다.

**비용:** 기본 이벤트 기록에서 최근 90일간 관리 작업을 조회하는 것은 무료다. 별도 추적, 장기 저장, 데이터 이벤트 수집 등은 비용이 발생할 수 있다.

**주의사항:** 기존 기록을 확인하려는 목적으로 불필요한 유료 로그 수집 설정을 추가하지 않는다.

**확인사항:** 문제가 발생하면 관련 작업 시간과 변경한 계정을 확인한다.

## 13. IAM (팀원 및 서버 권한 관리)

**용도:** AWS 사용자와 서버가 수행할 수 있는 작업을 제한한다.

**주의사항:** 필요 이상의 권한을 부여하면 실수로 다른 팀원의 서버나 보안 설정을 변경할 수 있다.

**구축 시:** 팀원별 담당 업무에 필요한 최소 권한만 부여하고, 권한을 부여한 뒤 실제 접근이 가능한지 시험한다.

**보안:** 루트 계정, 비밀번호, Access Key(접근 키)는 공유하거나 GitHub에 올리지 않는다. MFA(추가 인증)를 유지한다.

**종료 시:** 프로젝트가 끝나면 임시로 부여한 권한과 사용하지 않는 접근 키를 점검한다.

## 14. Route 53·ACM (도메인 및 HTTPS)

**Route 53:** 도메인과 홈페이지 주소를 연결하는 서비스다. 호스팅 영역, DNS 조회, 도메인 등록 등에 비용이 발생할 수 있다.

**ACM:** 홈페이지의 HTTPS 인증서를 관리한다. ALB에 사용하는 일반적인 비내보내기형 AWS 공인 인증서는 무료로 제공되지만, 인증서 유형에 따라 비용이 달라질 수 있다.

**주의사항:** DNS 설정을 잘못 변경하면 홈페이지 접속이 안 될 수 있다.

**구축 시:** 도메인 사용 여부, 인증서 연결 상태, HTTPS 접속 성공 여부를 확인한다.

**종료 시:** 더 이상 사용하지 않는 호스팅 영역과 도메인 자동 갱신 여부를 확인한다.

## 15. 데이터베이스 및 프로그램 설치

**현재 계획:** PostgreSQL 데이터베이스를 EC2에 설치하는 구성이므로, 별도 RDS 서비스가 필요한지는 팀장과 협의해야 한다.

**주의사항:** 데이터베이스 비밀번호와 인증 정보를 GitHub에 올리지 않는다. DB 포트를 인터넷에 공개하지 않는다.

**설치 시:** 서버에 필요한 프로그램만 설치하고, 설치 이후 서비스가 정상 작동하는지 확인한다.

**변경 시:** 프로그램 업데이트나 데이터베이스 변경 전에는 백업과 복구 방법을 확인한다.

**종료 시:** 필요한 데이터베이스 자료와 첨부파일을 함께 보관하고 복원 시험을 진행한다.

## 16. AWS 예산·크레딧·공통 비용 관리

**예산 알림:** 설정한 1달러 예산을 넘겨도 AWS 자원이 자동으로 중지되는 것은 아니다. 알림과 실제 비용 반영은 지연될 수 있다.

**크레딧:** 남은 크레딧과 실제 청구 금액은 구분한다. 계정의 무료/유료 플랜 상태, 크레딧 적용 대상 및 만료일을 확인한다.

**데이터 전송:** 인터넷으로 보내는 데이터나 가용 영역 간 통신에서도 별도 요금이 발생할 수 있다.

**리전 확인:** 서울 리전을 사용하더라도 다른 리전에 잘못 생성된 자원이 없는지 확인한다.

**자원 기록:** 생성된 AWS 자원의 이름, 수량, 담당자, 생성일, 삭제 예정일을 기록한다.

**추가 서비스:** 설계에 없는 유료 서비스를 새로 생성하기 전에는 용도와 예상비용을 검토하고 팀장 승인을 받는다.

## 17. 최종 자원 정리 시 주의사항

프로젝트 종료 후에는 서버를 중지하는 것으로 끝내지 않고 남아 있는 자원을 점검해야 한다.

**점검 대상:** EC2, EBS, 스냅샷, NAT Gateway, EIP, ALB, S3, WAF, CloudWatch 로그, Route 53 및 추가 생성한 유료 서비스.

**삭제 전:** 다른 팀원의 사용 여부, 최종 시연 완료 여부, 백업 및 복원 검증 결과를 확인한다.

**삭제 후:** 실제 자원이 삭제되었는지 확인하고, 비용 내역에 남아 있는 항목이 있는지 다시 점검한다.

**운영 원칙:** 모든 중요 자원의 생성·변경·삭제는 담당자와 협의하고 팀장 승인 후 진행한다.

## 2. 보안 및 접속 관련

-루트 계정과 비밀번호, AWS 접근 키는 팀원에게 공유하거나 GitHub에 올리지 않는다.

-팀원에게는 담당 업무에 필요한 권한만 부여한다.

-관리자 권한은 승인 없이 부여하지 않는다.

-보안 그룹을 임의로 변경하거나 DB 서버를 외부에 공개하지 않는다.

-현재 설계에서는 NAT 삭제 시 SSM 접속과 프로그램 설치가 안 될 수 있다.

-NAT 재생성 시 라우팅 설정과 SSM 연결을 다시 확인해야 한다.

-S3 Gateway Endpoint는 NAT와 별개로 사용할 수 있지만, 라우팅과 접근 권한을 확인해야 한다.

## 3. 자원 삭제 및 관리

-자원을 생성할 때 담당자, 생성일, 삭제 예정일을 기록한다.

-자원 삭제 전 다른 팀원이 사용 중인지 확인한다.

-서버 삭제 전 필요한 자료를 백업하고 복원 여부를 확인한다.

-NAT 삭제 시 EIP와 라우팅 설정을 함께 점검한다.

-프로젝트 종료 후 EC2, EBS, NAT, ALB, EIP, S3, WAF, CloudWatch 등 남은 자원을 확인한다.

-자원 생성과 삭제는 팀장 및 담당자와 협의 후 진행한다.

## 결론

- 서버 구축·시험이 이어지는 기간에는 NAT 유지
- 며칠간 사용하지 않는 기간에는 삭제 여부 검토
- 최종 시연과 백업이 끝나면 NAT 및 남은 공인 IP 정리
