# 클라우드 접근 통제 정책서

- 프로젝트: Haven
- 구분: 기본 2 도전(C2)
- 작성자: 김보람
- 작성일: 2026-11-27 (기존 11/26 결과 정리 및 GitHub 작업 기록 기준)

## 1. 목적 및 적용 범위

Haven AWS 계정과 서울 리전(ap-northeast-2)의 운영 자원에 대한 접근을 담당 업무별로 구분한다. 사용자에게는 필요한 작업만 허용하고, 서버에는 각 서버의 기능에 필요한 IAM 역할을 연결한다. 불필요한 접근, 무단 변경, 운영 자원의 임의 삭제와 인증 정보 노출을 방지하는 것이 목적이다. 본 정책서는 적용한 접근 통제와 향후 관리 기준을 구분하며, 별도 신규 AWS 설정을 의미하지 않는다.

## 4. 서버별 IAM 역할 및 자원 접근

11/13 Web 전용 역할 적용으로 기존 공통 역할을 Web/DB 역할로 분리하였다. 서버는 EC2 신뢰 정책을 사용하며, 사람의 장기 액세스 키를 서버에 저장하는 방식으로 권한을 제공하지 않는다.

| 자원/기능 | Web: haven-ec2-web-role | DB: haven-ec2-ssm-role |
|---|---|---|
| SSM 관리 | AmazonSSMManagedInstanceCore | 동일 |
| 서버 설정값 | /haven/* 읽기 | /haven/* 읽기 |
| S3 백업 | 지정 db-backups/* 경로 저장·조회 | 동일 |
| CloudWatch | /haven/web 로그 스트림 조회·생성·전송 | /haven/db 로그 스트림 조회·생성·전송 |
| SES | 서울 리전, 지정 identity 및 noreply@orchestration-haven.cloud 발신 주소로 제한된 SendEmail | 미부여 |
| 제한 | S3 파일 삭제, 파라미터 변경·삭제, 로그 삭제 미부여 | 동일, Web 전용 로그 정책 제거 확인(11/23) |

S3 백업 버킷은 퍼블릭 접근 차단, ACL 비활성화, SSE-S3 암호화를 적용하였다. S3 객체 접근은 지정 백업 경로를 기준으로 제한한다. 서버 관리 접속은 승인된 IAM 사용자와 SSM을 이용하며 일반 계정의 관리 세션은 허용하지 않는 기준을 적용한다.

## 5. 정책 구성 및 최소 권한 제한

| 주체 | 적용 정책 목록(11/26 결과 정리 기준) |
|---|---|
| 이민성 (14개) | Haven-Minsung-ALB-ACM-DNS-Policy, Haven-Minsung-CloudWatch-Logs-Manage, Haven-Minsung-Delete-Policy, Haven-Minsung-Infra-Policy, Haven-Minsung-PassRole-Policy, Haven-Minsung-Route53-Create, Haven-Minsung-Route53-Read, Haven-Minsung-Self-MFA-Policy, Haven-Minsung-SES-Read, Haven-Minsung-SessionManager-Policy, Haven-Minsung-WAF-Manage, Haven-Minsung-Web-InstanceProfile-Replace, IAMUserChangePassword, SignInLocalDevelopmentAccess |
| 안민수 (5개) | AWSCloudShellFullAccess, Haven-IAM-Self-MFA-Password-Policy, Haven-Minsoo-SessionManager-Policy, Haven-Minsoo-SSM-Policy, IAMUserChangePassword |
| 구민철 (4개) | Haven-IAM-Self-MFA-Password, Haven-Minchul-SG-Read, IAMUserChangePassword, SignInLocalDevelopmentAccess |
| 권혁민 (6개) | Haven-Hyeokmin-CloudWatch-Read, Haven-Hyeokmin-EC2-WAF-LogQuery-Read, Haven-Hyeokmin-WAF-Manage, Haven-IAM-Self-MFA-Password, IAMUserChangePassword, SignInLocalDevelopmentAccess |
| DB 역할 (4개) | AmazonSSMManagedInstanceCore, Haven-EC2-DB-Logs-Write, Haven-EC2-S3-Backup-Restore, Haven-EC2-SSM-Parameters-Read |
| Web 역할 (5개) | AmazonSSMManagedInstanceCore, Haven-EC2-S3-Backup-Restore, Haven-EC2-SSM-Parameters-Read, Haven-EC2-Web-CloudWatch-Write, Haven-EC2-Web-SES-Send |

- IAM 정책의 Action(작업), Resource(자원), Condition(조건)을 함께 검토한다. 서울 리전 조건을 적용할 수 있는 작업에 사용하고, Route 53·IAM 등 글로벌 서비스에는 해당 서비스의 자원·작업 범위를 검토한다.
- EC2 시작·중지는 Project=Haven, Owner=minsung 등 지정 태그를 적용하며, 생성 시 t3.small·t3.micro 및 공인 IP 자동 할당 제한을 사용한다. 운영 EC2 영구 삭제 권한은 주지 않고 시험용 삭제로 제한한다. SG 역시 시험용 삭제와 운영·기본 SG 보호를 구분한다.
- PassRole은 지정된 Web·DB 역할과 EC2 서비스로 제한한다. Route 53 조회 정책은 지정 호스팅 영역 상세 및 레코드 조회 등으로 제한하고, 생성 정책은 별도 관리한다.
- 12번 인프라 정책의 ConfigureHavenInfrastructureInSeoul Resource: "*"는 11/19 조장 결정에 따라 위험 수용으로 유지한다. 35번 인스턴스 프로파일 교체 권한은 서울 리전 제한이나 특정 서버 한 대로 제한되지 않으므로 잔여 위험으로 기록한다.
- 관리형 정책·인라인 정책 목록은 실제 사용자/역할 연결 기록을 기준으로 하며 GitHub 01~35번 파일 번호가 실제 정책 개수와 동일하다는 의미는 아니다.

## 6. 권한 변경·회수 및 종료 관리

1. 담당 업무에 필요한 작업과 자원 범위를 확인하고, 승인된 정책을 적용한다.
2. 허용되어야 하는 업무와 거부되어야 하는 접근을 구분하여 시험한다. 정책 시뮬레이터 결과와 실제 실행 결과를 구분한다.
3. AWS 저장본과 GitHub JSON을 대조하고 변경 이유, 허용/거부 결과 및 미확인 사항을 기록한다.
4. 종료 시 조장 승인 후에만 민성·혁민에게 필요한 삭제 권한을 임시 부여한다. 대상과 기존 정책을 기록하고 삭제 완료 후 임시 권한을 회수한다. 그룹·역할 등 다른 접근 경로와 기존 JSON을 다시 대조한다.
5. 업무 인계·종료 이후 불필요한 IAM 접근을 재검토하며, 보존과 삭제가 승인되기 전 실제 자원을 삭제하지 않는다. 현재 종료용 권한 부여·회수는 미실행이다.
