# 노푸른 화면 구현·시험 인계

## 담당 업무와 구현 화면

- Django 템플릿·CSS와 사용자 흐름 시험을 담당했다. 템플릿 원본은 [templates/](templates/), 정적 파일은 [static/](static/)에 있다.
- 공통 탐색, 로그인·가입, 내 기록 목록·상세·작성·수정·삭제 확인, 공유받은 목록·공유 관리, 계정 관리·변경 이력, 첨부 화면 및 공통 오류 화면을 준비했다.
- 화면별 URL·폼·context와 템플릿 연결 계약은 [앱 계약 5장](../신요찬/앱계약.md)을 따른다. 서버 설정·모델·migration은 화면 담당 범위가 아니다.

## 키보드·반응형·빈 목록·입력 안내

- 11/19 공유 설정에서 Tab·Shift+Tab 이동과 선택 표시, 아이디 입력 및 Enter 추가를 확인했다. 11/20 로그인·새 기록 작성·기록 상세에서 Tab·Shift+Tab 이동과 초점 표시를 확인했다. 전 화면 전수 검사는 아니다.
- 11/20 모바일 메뉴와 기록 작성·수정·상세·내 기록·공유 관리·공유받은 기록 빈 목록의 좁은 화면 표시를 확인했다. 모바일 메뉴는 375px이며, 다른 좁은 창 시험의 정확한 너비는 기록되지 않았다. 이 화면 배치 시험에서 각 기능 실행까지 확인한 것은 아니다.
- 11/23 관리자 계정 관리와 변경 이력을 모바일 모드 375px 및 좁힌 일반 창에서 확인했다. 표 오른쪽 내용과 버튼은 가로 스크롤로 볼 수 있었고 확인 범위에서 겹침이 없었다.
- 공유받은 기록의 빈 목록 안내와 공유 관리의 빈 공유 대상 안내를 확인했다. 11/20 기록 작성·수정의 빈 내용, 공유 대상 빈 아이디, 로그인 비밀번호 미입력, 첨부 미선택 안내를 확인했다. 해당 입력 안내 시험에서 확인하지 않은 서버 응답·상태는 성공으로 간주하지 않는다.

## 로그인 만료·CSRF·오류 화면

- 11/20 명시적 로그아웃 후 보호 기록 접근 시 로그인 화면을 확인했다.
- 11/24 자연 로그인 만료: 시크릿 창에서 15:15 로그인 후 16:16~16:17경 새로고침하자 로그인 화면이 표시됐다. 새로고침 시각은 사용자 기억 기준이다. 전달받은 설정은 `SESSION_COOKIE_AGE = 3600`, `SESSION_EXPIRE_AT_BROWSER_CLOSE = True`, `SESSION_SAVE_EVERY_REQUEST = False`다.
- 11/24 CSRF 쿠키 삭제 후 저장 요청에서 403 안내 화면을 확인했다. 로그아웃 주소 GET 요청에서 405, 큰 본문 저장 요청에서 413 화면을 확인했다.
- 11/11 공통 403·404, 11/12 첨부 2개 동시 업로드에 따른 공통 400 화면을 확인했다. 이는 이전 배포본의 결과다. 11/11 빈 기록 제출은 브라우저에서 차단돼 그 조건의 서버 400 응답을 확인하지 못했다.
- 위 추가 시험의 오류 코드는 화면 표시 기준이며 실제 HTTP 상태는 별도 측정하지 않았다.

## 2026-11-25 비활성 계정과 로컬 500 화면

- **09:43 기존 세션:** 운영 사이트에서 일반 Chrome 창의 B 로그인 상태를 유지하고 별도 시크릿 창의 관리자 `op_pureun`으로 B를 비활성화했다. B 창 새로고침 후 로그인 상태가 해제됐다.
- **09:44 신규 로그인:** 비활성 B 로그인 시 “로그인할 수 없습니다. 아이디와 비밀번호를 확인해 주세요.”가 표시됐다. 시험 시각은 기존 상세 검증 기록에 기재된 값을 인용했다. 시험 후 B를 다시 활성화하고 정상 로그인을 확인했다. 복구 시각은 미기록이다. [증거](시연증거/20_비활성계정_로그인차단.png)
- **10:32 로컬 500 화면:** 시험 시각은 기존 상세 검증 기록에 기재된 값을 인용했다. Windows·Chrome, Django 5.2.19, 로컬 PostgreSQL 16에서 `DJANGO_DEBUG=0`, `DJANGO_HTTPS=0`, `python manage.py runserver 127.0.0.1:8000 --insecure`로 실행했다. 신요찬 안내에 따라 로컬 `postgresql-x64-16` 서비스를 중단하고 로그인 요청을 보냈다. 장시간 로딩 후 공통 500 화면과 안내 문구가 표시됐고 CSS 적용 및 상세 내부 오류 정보가 화면에 노출되지 않음을 확인했다. [증거](시연증거/21_500_오류화면.png)
- PostgreSQL 서비스 Running 상태 복구와 Django 재실행 후 로그인 화면 표시를 확인했다. 복구 후 실제 로그인은 시험하지 않았다. 로딩 지연 원인은 미확인이고 로컬 migration 5개는 미적용 상태였다. 운영에서 500을 발생시키지 않았으며 실제 HTTP 상태는 측정하지 않았다.
- 비활성 처리의 코드·자동 테스트 근거와 신요찬의 이전 확인은 [상세 기록](1회차_앱_검증기록.md)에 있다. 이번 화면 시험에서 자동 테스트를 직접 실행한 것은 아니다.

## 시험 범위와 남은 확인

- 브라우저 화면과 사용자 조작 결과에 대한 기록이다. 모든 화면·기능, 키보드 조작, 화면 너비를 전수 검사하지 않았다.
- 11/24 재시험은 당시 최종 배포로 확인된 `5d0e370` 기준이며 이후 운영 배포 변경 여부는 이 기록에서 확인되지 않는다.
- 11/23 관리자 화면 조작 중 `test11`을 실수로 활성화했다가 다시 비활성화해 원상복구했다. 사용자 보고에 따르면 팀장에게 이미 알렸으며, 11/25 B 시험과 별개다.
- 일부 과거 시험의 정확한 시각·너비와 11/25 계정 복구 시각은 미기록이다. 500 복구 후 실제 로그인, 지연 원인과 미적용 migration의 영향은 확인하지 않았다.
- 최종 인계 자료는 기존 저장소에 준비돼 있다. 신요찬에게 경로·context, 안민수에게 사용자 흐름 시험·가림 화면을 별도로 최종 전달했는지는 확인되지 않았다.
