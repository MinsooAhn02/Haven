# 1회차 화면 배치 초안

> 이 문서는 화면의 배치와 문구를 논의하기 위한 초안이다. 실제 Django 프로젝트와 신요찬의 URL·폼·context 계약이 아직 없으므로, 동작하는 화면이나 확정된 필드명이 아니다. URL 연결, 서버 코드, 템플릿 코드는 이번 작업에 포함하지 않는다.

## 공통 화면 원칙

- 화면 위쪽에는 서비스 이름과 현재 화면 제목을 둔다. 사용자는 제목만 보고도 지금 어디에 있는지 알 수 있다.
- 입력칸마다 바로 위에 설명이 있는 이름표(label)를 붙인다. 예를 들어 입력칸의 이름을 placeholder에만 넣지 않는다.
- 오류가 있으면 입력칸 근처에 무엇이 잘못됐고 어떻게 고칠지 글로 표시한다. 색만 바꾸어 오류를 알리지 않는다.
- 입력·저장·삭제 같은 주요 버튼은 화면에서 찾기 쉽게 배치하고, 취소/이동 버튼과 구분한다.
- 로그인 후 사용하는 모든 화면(내 기록 목록, 상세, 작성·수정, 삭제 확인)에는 공통 메뉴와 함께 현재 위치를 표시한다. 표시 방법과 위치 정보 제공 방식은 **계약 확인 필요**.
- 입력 오류가 있으면 폼 위쪽 요약에서 각 오류 항목을 찾을 수 있게 하고, 오류 후 첫 번째 오류 입력칸으로 키보드 초점을 이동하도록 설계한다. 오류 식별자 연결과 초점 이동 시점은 **계약 확인 필요**.
- 기록 본문은 일반 글자로 보여준다. 사용자가 입력한 HTML 모양의 문자열도 웹 코드로 실행하지 않는다는 전제다.
- 아래 문구와 필드명은 제안이다. 폼 계약을 받으면 서버가 정한 이름과 검증 결과에 맞춰 조정한다.

## 공통 탐색 메뉴

### 로그인 전

- 서비스 이름: `Haven 기록`
- 메뉴: `로그인`, `회원가입`
- 로그인/회원가입 화면에서는 현재 메뉴를 표시해 사용자가 위치를 알 수 있게 한다.

### 로그인 후

- 서비스 이름: `Haven 기록`
- 메뉴: `내 기록`, `로그아웃`
- 현재 로그인한 계정 이름을 메뉴 근처에 표시한다. 예: `로그인 계정: pureun-demo`
- 로그인 후 사용하는 각 화면에는 메뉴 근처에 현재 위치를 표시한다. 구체적인 경로 표시 방식은 **계약 확인 필요**.
- 이번 회차에는 공유 기능을 구현하지 않으므로 `공유받은 기록` 메뉴는 넣지 않는다.
- 로그아웃은 링크가 아니라 제출 버튼 형태로 둔다. 로그아웃 방식은 서버 계약에 맞춘다.

## 1. 로그인

**화면 제목:** 로그인

**짧은 안내:** `내 기록을 보려면 로그인해 주세요.`

**입력칸:**

1. 아이디 — 예: `아이디를 입력하세요`
2. 비밀번호 — 입력 내용은 화면에 글자로 드러나지 않게 표시

**버튼과 이동:**

- 주요 버튼: `로그인`
- 보조 이동: `처음 오셨나요? 회원가입`

**오류 안내 초안:**

- 입력이 빠진 경우: `아이디와 비밀번호를 모두 입력해 주세요.`
- 로그인에 실패한 경우: `로그인할 수 없습니다. 아이디와 비밀번호를 확인해 주세요.`
- 계정 존재 여부를 구분해 알려주지 않는 일반 오류를 사용한다.

**배치:** 좁은 화면에서도 한 열로 입력칸을 놓고, 로그인 버튼은 입력칸 아래에 둔다.

## 2. 회원가입

**화면 제목:** 회원가입

**짧은 안내:** `새 계정을 만듭니다. 비밀번호를 안전하게 입력해 주세요.`

**입력칸:**

1. 아이디
2. 비밀번호
3. 비밀번호 확인

비밀번호 정책과 아이디 허용 규칙은 실제 폼 계약의 검증 결과로 안내한다. 비밀번호와 확인값은 가입 실패 후에도 입력칸에 다시 채우지 않는다.

**버튼과 이동:**

- 주요 버튼: `가입하기`
- 보조 이동: `이미 계정이 있나요? 로그인`

**오류 안내 초안:**

- 각 입력칸에 해당하는 오류를 그 입력칸 가까이에 표시한다.
- 폼 위쪽에는 `입력 내용을 확인해 주세요.`처럼 오류가 있음을 알리는 요약을 둔다.
- 아이디 중복/형식 오류는 서버가 돌려준 안내를 표시한다.

**배치:** 안내문, 오류 요약, 아이디, 비밀번호, 비밀번호 확인, 가입 버튼 순으로 위에서 아래로 놓는다.

## 3. 내 기록 목록

**화면 제목:** 내 기록

**짧은 안내:** `내가 작성한 기록을 확인하고 관리할 수 있습니다.`

**상단 동작:**

- 주요 버튼: `새 기록 작성`
- 공통 탐색 메뉴와 로그인 계정 표시

**기록이 있을 때:**

- 최신 기록부터 한 건씩 목록으로 보여준다.
- 각 항목에는 기록 제목, 작성/수정 시각(제공되는 경우), `열기` 동작을 둔다.
- 긴 제목도 잘리지 않도록 줄바꿈한다.
- 한 페이지에 기록을 최대 20개 표시한다.
- 목록 위나 아래에 `이전 페이지`, `다음 페이지` 버튼을 둔다. 첫 페이지에서는 `이전 페이지`, 마지막 페이지에서는 `다음 페이지`를 사용할 수 없음을 표시한다. 실제 페이지 정보와 이동 연결 방식은 **계약 확인 필요**.

**기록이 없을 때 안내:** `아직 기록이 없습니다. 첫 기록을 작성해 보세요.`

**빈 목록 버튼:** `새 기록 작성`

**오류 안내:** 목록을 불러오지 못한 경우 기록이 없는 것처럼 표시하지 않고 `기록을 불러오지 못했습니다. 잠시 후 다시 시도해 주세요.`처럼 실패임을 구분한다.

## 4. 기록 상세

**화면 제목:** 기록 상세

**본문 영역:**

- 기록 제목을 가장 눈에 띄게 표시한다.
- 작성 시각과 마지막 수정 시각을 표시한다(서버가 제공하는 경우).
- 기록 본문을 읽기 쉬운 줄 간격으로 표시하고 긴 줄은 화면 너비 안에서 줄바꿈한다.
- 사용자 본문은 HTML로 실행하지 않고 일반 텍스트로 표시한다.

**동작 버튼:**

- `내 기록 목록`으로 돌아가기
- 소유자에게만 `수정`, `삭제` 동작 표시
- 이번 회차에는 공유 기능이 없으므로 읽기 전용 공유 상태 표시는 대상이 아니다. 추후 공유 화면을 만들 때는 읽기 전용임을 분명히 표시한다.

**안내 문구:** 기록을 찾을 수 없거나 볼 권한이 없을 때는 동일한 안내 화면을 사용한다. 구체적인 타인의 기록 존재 여부를 드러내지 않는다.

**현재 위치 표시:** 로그인 후 공통 메뉴와 함께 현재 위치를 표시한다. 상세한 표시 형식과 값은 **계약 확인 필요**.

## 5. 기록 작성·수정

**화면 제목:**

- 새 기록이면 `새 기록 작성`
- 기존 기록이면 `기록 수정`

**짧은 안내:** `제목과 내용을 입력해 주세요. 기록은 일반 텍스트로 저장됩니다.`

**입력칸:**

1. 제목 — 명세 제안은 최대 200자. 입력칸 아래 글자 수/제한 안내는 계약이 확정된 경우에 표시
2. 내용 — 여러 줄 입력이 가능한 큰 입력칸

제목과 내용 모두 명확한 label을 붙인다. 오류가 난 경우 해당 입력칸과 오류 문구를 연결한다. 실패 후 안전한 입력은 유지하되 비밀번호 같은 비밀 입력은 이 화면에 없고, 사용자 HTML은 실행하지 않는다.

**버튼과 이동:**

- 새 기록: `저장`, `취소`
- 수정: `변경사항 저장`, `취소`
- 취소는 새 기록이면 내 기록 목록으로, 수정이면 상세로 돌아가는 방향을 제안한다. 실제 목적지는 URL 계약에 맞춘다.

**오류 안내 초안:**

- 제목이 비어 있음: `제목을 입력해 주세요.`
- 제목/본문 형식 또는 길이 오류: 해당 입력칸 옆에 서버 검증 메시지 표시
- 저장 실패: 성공한 것처럼 이동하지 않고 `저장하지 못했습니다. 입력 내용을 확인한 뒤 다시 시도해 주세요.` 표시

**현재 위치 표시:** 로그인 후 공통 메뉴와 함께 `내 기록 > 새 기록 작성` 또는 `내 기록 > 기록 수정`처럼 현재 위치를 표시한다. 실제 위치 정보와 이동 연결은 **계약 확인 필요**.

## 6. 기록 삭제 확인

**화면 제목:** 기록 삭제 확인

**확인할 대상:** 삭제할 기록의 제목을 표시한다. 사용자가 어떤 기록을 지우려는지 확인할 수 있어야 한다.

**경고 문구 초안:** `“[기록 제목]” 기록을 삭제할까요? 삭제하면 목록에서 더 이상 볼 수 없습니다.` 실제 복구 가능 여부는 서버의 삭제 정책이 확정된 뒤 정확하게 표현한다.

**버튼과 이동:**

- 위험 동작 버튼: `삭제`
- 취소 버튼: `취소하고 기록으로 돌아가기`
- 명세 제안상 화면을 여는 GET 요청만으로 삭제하지 않고, 사용자가 `삭제`를 눌러 제출했을 때만 삭제한다. 요청 방식과 CSRF 처리는 서버 계약에 맞춰 연결한다.

**오류 안내:** 권한이 없거나 기록이 없는 경우 상세 정보 대신 일반 오류 화면을 사용한다. 삭제 요청이 실패하면 성공 안내를 보여주지 않는다.

**현재 위치 표시:** 로그인 후 공통 메뉴와 함께 `내 기록 > 기록 상세 > 기록 삭제 확인`처럼 현재 위치를 표시한다. 실제 위치 정보와 이동 연결은 **계약 확인 필요**.

## 공통 오류 화면 (403·405·500)

이 항목은 기존 여섯 화면에 더하는 공통 처리 화면이다. 서버가 오류 상태를 반환했을 때 성공한 것처럼 보이지 않도록 오류 종류별 제목과 안내를 보여준다.

| 오류 상태 | 화면 제목 | 안내 문구 초안 |
|---|---|---|
| 403 | 요청이 거부되었습니다 (403) | 이 요청을 처리할 권한이 없습니다. 입력한 내용은 변경되지 않았습니다. |
| 405 | 지원하지 않는 요청입니다 (405) | 이 화면에서 허용하지 않는 방법으로 요청했습니다. 이전 화면에서 다시 시도해 주세요. |
| 500 | 일시적인 오류가 발생했습니다 (500) | 요청을 처리하는 중 문제가 발생했습니다. 잠시 후 다시 시도해 주세요. |

- 각 오류 화면에는 안내와 `돌아가기` 버튼을 둔다.
- 버튼이 이동할 목적지, 로그인 여부에 따른 이동, 오류 템플릿/경로 연결은 **계약 확인 필요**.
- 오류 응답의 기술 세부사항이나 비밀값은 화면에 표시하지 않는다.
- 404(없는 기록과 권한 없는 기록의 공통 화면), 413(요청 크기 초과) 등 다른 상태의 문구와 연결은 **계약 확인 필요**.

## 입력 오류 표시 공통 규칙

- 입력 폼 위쪽의 오류 요약에 문제가 난 항목 이름을 나열하고, 사용자가 해당 입력칸을 찾을 수 있게 한다.
- 오류가 있으면 화면 표시 후 첫 번째 오류 입력칸으로 키보드 초점을 이동하도록 설계한다.
- 각 입력칸 가까이에도 오류 원인과 수정 방법을 글로 표시하고, 입력칸과 오류 안내를 연결한다.
- 실제 오류 context 형식, 항목 연결 방식, 초점 이동 조건은 **계약 확인 필요**.

## 검토할 사용자 흐름

아래는 배치 초안을 실제 화면으로 구현한 뒤 확인할 흐름이며, 아직 실행하거나 검증한 결과가 아니다.

1. 로그인 화면에서 회원가입 화면으로 이동하고, 가입 후 로그인할 수 있는지 확인
2. 로그인 후 공통 메뉴에서 내 기록 목록으로 이동할 수 있는지 확인
3. 빈 목록 안내에서 새 기록 작성으로 이동할 수 있는지 확인
4. 기록을 저장한 뒤 목록과 상세에서 제목/본문을 확인할 수 있는지 확인
5. 상세에서 수정과 삭제 확인으로 이동하고 취소 동작이 맞는지 확인
6. 삭제 확인 화면을 열기만 해서는 기록이 삭제되지 않는지 확인
7. 키보드만으로 입력·저장·취소가 가능하고 좁은 화면에서도 주요 동작을 찾을 수 있는지 확인

## 계약을 받은 뒤 확정할 사항

- 실제 템플릿 경로와 파일명
- URL 이름/namespace 및 버튼별 이동 주소
- 폼 클래스와 정확한 필드명, label, validation/error 형식
- 각 화면이 받는 context 값과 날짜/페이지 표시 방식
- 페이지당 20건의 페이지 정보와 이전/다음 이동에 필요한 context 및 URL 연결
- 로그인 실패·필드 검증·권한 거부·저장 실패의 응답과 메시지
- 오류 요약의 필드 식별 정보와 첫 오류 초점 이동을 위한 렌더링 조건
- 403/405/500 및 404/413 오류 화면의 템플릿 연결, 돌아가기 목적지와 로그인 상태별 동작
- 삭제 요청 방식, 확인/취소 이동, 삭제 후 화면
