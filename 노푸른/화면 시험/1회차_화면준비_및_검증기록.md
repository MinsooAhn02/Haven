## 신요찬에게 필요한 화면 계약

아래 계약과 샘플 context를 전달받은 후 Django 템플릿을 구현/연결한다.

1. 프로젝트/앱의 템플릿 디렉터리, 템플릿 로더 설정, 화면별 템플릿 파일명
2. 확정 URL pattern 이름과 namespace, 각 화면의 method 및 성공/실패 redirect 경로
3. 로그인/가입/기록 폼의 이름, field 이름, label/help text/error 표시 방식, CSRF 처리
4. 각 화면의 context 키와 자료 형태: 사용자, 목록/페이지, 기록, 소유/읽기 전용 상태, 오류/메시지
5. 폼 실패 HTTP 상태와 안전하게 보존되는 값, 비밀번호 미재표시 기준
6. 삭제 확인 GET/POST 동작, 존재하지 않거나 권한 없는 기록의 화면 계약
7. 가상 계정·기록 fixture 및 실행/검증 명령

## 2026-11-06 정적 시안 보완 기록

- HTML 시안 준비: 완료. 로그인, 회원가입, 내 기록 목록, 기록 상세, 작성·수정, 삭제 확인의 6개 시안과 공통 오류(403/405/500) 미리보기를 마련했다. 이는 정적 HTML 디자인 시안이며 Django 템플릿 연결 완료를 뜻하지 않는다.
- 공통 오류 화면: `공통오류_디자인_시안.html`에 403·405·500 예시를 각각 배치했다. 실제 서비스에서는 상황에 맞는 하나의 오류 화면만 표시하는 디자인 예시다.
- 화면 간 링크: HTML 7개를 대상으로 상대 파일 링크와 내부 조각 링크를 정적으로 확인했다. 확인 결과 모든 대상 파일과 조각 ID를 찾았다. 로그인↔회원가입, 목록→상세/작성, 상세→목록/수정/삭제, 작성·수정 취소 동선을 미리보기 파일에 연결했다. 작성 당시 HTML 미리보기에서 이동을 직접 확인했다고 기록했으나, 이 PR 검토에서는 브라우저로 재현하지 않았다. 페이지 이동은 실제 기능처럼 연결하지 않았다.
- 목록 페이지 표시: 페이지당 최대 20개 안내를 유지했다. 1페이지 예시의 이전 페이지는 비활성 표시이며 다음 페이지도 미리보기 전용 비활성 표시다.
- 입력 오류 안내: 로그인·회원가입·작성·수정 시안에 펼쳐 볼 수 있는 오류 요약 예시를 추가하고, 요약 항목에서 해당 입력칸으로 이동하도록 연결했다. 입력의 `aria-describedby`에 안내용 ID를 참조하도록 했다. 이는 정적 마크업 확인이며 실제 오류 렌더링/초점 이동 동작 시험은 하지 않았다.
- 브라우저 시험: 작성자는 HTML 미리보기에서 화면 간 이동을 직접 확인했다고 기록했다. 이번 PR 검토에서 독립적으로 재현한 브라우저 시험은 하지 않았으며, 데스크톱/작은 화면 렌더링, 키보드 조작, 화면낭독기 동작도 검증하지 않았다. 정적 링크·조각 대상은 화면 간 링크 항목을 참조한다.
- Django 연결 및 서버 시험: 미실시. 저장소에서 Django 프로젝트를 확인하지 못했고, 신요찬의 확정 URL·폼·context 계약도 전달받지 못했다.
- 서버 URL, 폼 필드 계약, context 구조, 서버 오류 처리는 임의로 확정하지 않았다. 실제 서비스에 연결하기 전 담당자 계약 확인이 필요하다.

- 병합 전 독립 정적 재검증: Python HTMLParser로 HTML 7개의 로컬 링크·조각 대상 44건을 확인했다. 브라우저 렌더링 시험은 포함하지 않았다.
