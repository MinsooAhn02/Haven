# 앱 보안 검증 요약 (신요찬, 최종 보고·발표용)

앱(Django)에 넣은 보안 설정 하나하나에 대해 **의도 → 어떻게 검증했나 → 결과 → 한계**를 한 표로 모았다. "설정했다"가 아니라 "의도대로 동작하는지 확인했다"를 보여 주는 것이 목적이다. 자세한 내용은 각 줄의 근거 문서에 있다.

- 기준: main `c6ce842`(11/26, #254 4회차 10장 포함)에 이번 PR의 4회차 8·9장을 더한 상태. 운영 최종 배포본은 11/19 `5d0e370`이고(11/24 앱 코드 마감, 재배포 없음), 앱 코드는 `d654fca` 뒤로 바뀌지 않았다.
- 시험 ID는 구현명세 8장 그대로다. ASVS 대응은 구민철 매핑 표가 맡는다.

## 1. 검증은 세 겹으로 했다

## 3. 검증으로 찾아 고친 것

검증이 형식이 아니었다는 근거다.

- **업로드가 강제로 끊기면 임시 파일이 남는 결함**: 3회차 실제 서버 확인에서 찾았다. 코드를 고치고 시험을 추가했다.
- **테스트 빈틈 4개**: 결함 주입에서 잡히지 않은 결함을 보고 테스트를 보강했다(2회차 2, 3회차 2).
- **운영 관리자 메뉴 누락**: 조장이 운영 확인에서 찾았다. 화면 메뉴를 추가했고(#159), 다시 빠지지 않게 테스트로 고정했다(#167).
- **로그인 제한의 "실제 IP로 세는가"**: 1차에서는 DB 키 2개가 "사용자 2명"인지 "ALB 노드 2개"인지 구분이 안 됐다. 2차에서 실제 IP로 계산한 키와 대조해 확정했다.
- **WAF 오탐(혁민)**: 비밀번호의 `!@#`와 XMP PDF가 걸리는 것을 찾았다. 예외를 둔 채 Block했고, Block 뒤 같은 입력이 통과하는 것을 확인했다(C4).

## 4. 확인하지 못한 것

- 동시에 몰린 로그인 실패 요청(제한을 조금 넘길 수 있음)
- 운영 사이트에서 모든 기능을 자동으로 다시 돌리는 시험. 운영 확인은 항목별 수동·CLI 확인이다.
- 이미 내려받은 첨부의 회수(설계상 불가)
- MFA, 비밀번호 변경·재설정, 계정 복구(기능 없음, 명세 범위 밖)
