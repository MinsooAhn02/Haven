## 5. 03 — 공통 실행 계약 확정

### 버전과 원본 경로

- [ ] 실제 사용 가능한 Python/Django/PostgreSQL/driver 조합을 요찬님과 맞춘다. 버전 선택 이유·지원/호환 확인 근거·검토일을 기록하고 추정 버전을 확정값으로 쓰지 않는다.
- [ ] `manage.py`가 있는 위치·실행 작업 디렉터리·settings/WSGI·의존성 파일 경로를 실제 구조로 확정한다.
- [ ] 노푸른 템플릿/static은 원본 경로를 참조한다. settings 반영은 요찬님에게 요청하고 경로를 복사해 별도 관리하지 않는다.
- [ ] 로컬 PostgreSQL은 개발 전용 DB로 준비한다. 기존 설치가 있으면 활용하고, 새 설치가 필요하면 팀이 재현할 방식 하나를 정한다. Docker를 새 필수 도구로 임의 도입하지 않는다.
- [ ] 로컬 개발용 계정과 CI 시험용 계정을 구분한다. 시험 runner가 별도 시험 DB를 생성/삭제하는지 확인하고 필요한 권한을 개발 전용 범위로 제한한다. 이를 운영 runtime 권한에 복사하지 않는다.

### 환경변수 계약

변수 이름은 요찬님 settings가 실제 읽는 값과 일치시킨다. 아래는 필요한 설정 항목이며 새 이름을 강제하는 목록이 아니다.

| 설정 | 로컬/CI 기준 | 확인할 점 |
|---|---|---|
| Django Secret·DEBUG·허용 host | 개발/시험 전용 값, loopback host | 운영 Secret을 재사용하지 않음 |
| DB host/port/name/user/password | 개인 로컬 DB / CI 임시 DB | 운영 DB를 가리키지 않음 |
| settings 모듈·CSRF origin | 실제 모듈·브라우저 접속 origin | HTTP 로컬과 HTTPS 운영 값 구분 |
| static·첨부·임시 경로 | 합의한 원본/로컬 저장 위치 | 개인 파일이 Git에 들어가지 않음 |
| 메일 backend | 로컬/CI는 실제 전송 없는 시험 방식 | AWS/메일 키 없이 실행 가능 |
| migration 인증 | 운영 배포 때만 별도 공급 | 상시 runtime 인증과 분리 |

- [ ] 필수값 누락 시 동작을 확인한다. 잘못된 DB 연결을 SQLite로 조용히 대체하거나 운영 인증정보를 기본값으로 쓰지 않도록 요찬님과 맞춘다.
- [ ] `.env`를 읽는 주체·설치 의존성·실행 위치를 확정한다. 환경변수 직접 공급 방식을 쓰면 그 절차를 적는다.
- [ ] `.env.example`에는 placeholder만 남긴다. 개발/시험 Secret도 운영에 사용할 수 있는 실제 비밀값을 넣지 않는다.

**완료 조건:** 팀원이 앱 루트·설치 파일·환경변수 공급 방식·DB 준비·실행 명령을 추측하지 않고 따라 할 수 있다.
