# EC2 중지·시작 설명 (결정 4번)

결정 4번: **평일 09:00~21:00만 가동.** 매일 밤·주말에는 `nat-down` + EC2 중지, 아침에는 `nat-up` + EC2 시작.

## 매일 쓰는 명령

```bash
# 21시
bash night.sh
# 09시
bash morning.sh
```

미리보기는 앞에 `DRY_RUN=1`을 붙인다. 예: `DRY_RUN=1 bash night.sh`

## 파일

| 파일 | 하는 일 |
|---|---|
| `ec2-stop.sh` | web-1을 먼저 끄고 db-1을 끈 뒤, 둘 다 꺼졌는지 확인한다. 앱이 켜진 채로 DB가 먼저 꺼지지 않게 하는 순서. |
| `ec2-start.sh` | db-1을 먼저 켜고 web-1을 켠다. 그다음 공인 IP가 없는지 확인하고, 사설 IP를 출력하고, SSM 연결 상태(Online)를 확인한다. |
| `night.sh` | 밤 21시용. `ec2-stop` 다음에 `nat-down`을 실행한다. |
| `morning.sh` | 아침 09시용. `nat-up` 다음에 `ec2-start`를 실행한다. |
| `common.sh`의 `find_server` | 이름 하나(web-1 또는 db-1)로 서버 ID를 찾는다. 이름마다 한 번씩 부른다. |

## night·morning이 따로 있는 이유

`ec2-stop.sh`와 `nat-down.sh`를 차례로 쳐도 같은 일을 할 수 있다. 그래도 묶음 스크립트를 둔 이유는 **매일 두 번, 손으로 치다가 생기는 실수를 막기 위해서**다.

| 실수 | 묶음이 막는 방법 |
|---|---|
| 하나를 깜빡함. EC2만 끄고 NAT를 안 끄면 밤새 하루 약 $0.9가 나간다. NAT는 콘솔에서 잘 안 보여 놓치기 쉽다. | 결정 4번이 "nat-down + EC2 중지"를 한 세트로 정했다. 명령 하나로 둘 다 한다. |
| 아침에 순서를 틀림. EC2를 먼저 켜면 NAT가 없어 SSM 연결이 안 되고, ec2-start가 5분 기다리다 실패한다. | morning은 항상 NAT 먼저, EC2 나중으로 실행한다. |
| 앞의 것이 실패하면 거기서 멈춤. ec2-stop이 에러 나면 nat-down을 잊기 쉽다. | night는 하나가 실패해도 다른 하나는 끝까지 해서 요금을 하나라도 더 멈춘다 (시험 N2). |
| NAT가 이미 켜져 있는데 또 켬. | morning이 확인하고 nat-up을 건너뛴다 (시험 M1). |
| 주말이나 밤에 실수로 켬. | morning이 시간을 확인하고 멈춘다 (시험 M3~M5). |
| 시험용 EC2를 안 지우고 퇴근. | night가 마지막에 "아직 켜진 서버 있음"을 알린다. |

정리하면 이렇게 나뉜다.
- **stop·start, nat-up·nat-down**: 부품. 하나씩 따로 쓸 때(예: 서버만 재시작) 쓴다.
- **night·morning**: 매일 쓰는 버튼.

## 예외 처리 (가짜 시험 20개로 확인, `faketest설명.md` 참고)

- 이미 꺼졌거나 이미 켜져 있으면 아무것도 안 하고 정상 종료한다. 두 번 돌려도 괜찮다.
- 켜지는 중이거나 꺼지는 중이면 끝날 때까지 기다렸다가 처리한다.
- 서버가 없거나, 2대 이상이거나, state 파일의 ID와 다르면 아무것도 하지 않고 멈춘다.
  - **0대**: 아직 안 만들었거나 지워졌다 (시험 S4).
  - **2대 이상**: build.sh를 실수로 두 번 돌렸거나, 누가 같은 이름으로 하나 더 만들었다. 엉뚱한 서버를 끄지 않도록 멈춘다 (시험 S5).
  - **state 파일과 다름**: 서버를 삭제하고 다시 만든 경우 (시험 S6).
- 10분 안에 꺼지지 않거나, 공인 IP가 붙어 있으면 멈추고 알린다.
- SSM 조회 권한이 없으면 경고만 하고 넘어간다. 이때는 연결확인표 SSM-01로 직접 확인한다.
- **night**: EC2 중지가 실패해도 NAT는 끝까지 끈다. 아직 켜진 시험용 서버가 있으면 알린다.
- **morning**:
  - 주말이거나 09~21시 밖이면 멈춘다 (결정 4번). 민수 허락을 받았으면 `ALLOW_OFFHOURS=1 bash morning.sh`.
  - NAT가 이미 켜져 있으면 nat-up을 건너뛴다. NAT가 2개 생기지 않는다.
  - nat-up이 실패하면 EC2를 켜지 않는다. NAT 없이 켜 두면 요금만 나간다.

## 매일 밤 지우고 아침에 다시 만들면 뭐가 바뀌나

**NAT 쪽만 바뀐다.** EC2는 중지만 하므로 그대로다.

| 구분 | 매일 바뀜? | 저장 위치 |
|---|---|---|
| NAT Gateway ID (`nat-...`) | **바뀜** (지웠다 새로 만들어서) | `state/ap-northeast-2-nat.env`. nat-up이 아침에 새로 쓰고 nat-down이 밤에 지운다. |
| EIP ID (`eipalloc-...`)와 NAT의 공인 IP | **바뀜** | 위와 같은 파일 |
| rt-private의 0.0.0.0/0 경로 | 가리키는 대상만 바뀜. 밤에는 blackhole(갈 곳 없음), 아침에는 새 NAT | 경로표 자체는 그대로 |
| VPC, 서브넷, SG, 경로표, S3 Endpoint ID | 안 바뀜 | `state/ap-northeast-2.env` (build.sh가 한 번 씀) |
| EC2 인스턴스 ID (web-1, db-1) | 안 바뀜. 중지는 삭제가 아니다 | 위와 같은 파일 |
| EC2 사설 IP | 안 바뀜 | 민수에게 한 번만 전달 |
| EC2 디스크 (DB 데이터 포함) | 안 바뀜 (EBS 요금은 중지 중에도 나감) | |

그래서 state 파일을 두 개로 나눴다. 매일 바뀌는 NAT 정보와 한 번 만들면 그대로인 정보를 따로 둔다.

## 신경 쓸 점

- **바깥에서 보이는 출구 IP(NAT 공인 IP)가 매일 바뀐다.** 서버가 인터넷으로 나갈 때 쓰는 주소다. 지금은 GitHub, apt, SES, SSM 모두 우리 IP를 허용 목록에 넣는 방식이 아니라 문제없다. 나중에 "우리 서버 IP만 허용"하는 외부 서비스가 생기면 문제가 된다.
- **증거 자료에 NAT ID를 적을 때는 날짜를 같이 적는다.** 날마다 다른 값이다.
- **서버 ID나 사설 IP가 바뀌는 경우는 서버를 삭제(terminate)하고 다시 만들 때뿐이다.** 이때는 ec2-stop·ec2-start가 "state 파일 ID와 다름"이라며 멈춘다 (시험 S6).

## 필요한 IAM 권한 (보람 확인)

- `ec2:StopInstances`, `ec2:StartInstances`. 가능하면 태그 `Project=Haven` 서버에만.
- `ssm:DescribeInstanceInformation`(읽기 전용)은 선택. 없으면 경고만 하고 넘어간다.
