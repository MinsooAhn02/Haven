# 가짜 시험 설명 (test/ec2-fake-test.sh, test/alb-fake-test.sh, test/cw-fake-test.sh)

EC2 중지·시작 스크립트(`ec2-stop.sh`, `ec2-start.sh`, `night.sh`, `morning.sh`)가
예외 상황에서도 의도대로 움직이는지, **진짜 AWS 없이** 확인하는 시험이다.

## 실행

```bash
cd 이민성/infra
bash test/ec2-fake-test.sh
```

마지막 줄이 `결과: PASS 20 / FAIL 0`이면 통과.

## 안전장치

- 진짜 `aws` 대신 **가짜 aws**를 먼저 부르게 한다. 가짜는 서버 상태를 메모 파일에 적어 둔다.
- 스크립트를 **임시 폴더에 복사**해서 돌린다. 진짜 `state/` 파일을 읽거나 지우지 않는다.
- 진짜 AWS 로그인 정보를 막는다. 가짜 aws가 안 잡히면 시험을 시작하지 않는다.
- morning 시간 시험은 **가짜 시계**(시·요일만 바꿈)를 쓴다.

## 결과 읽는 법

`PASS  S4 db-1 없음 → 하나도 안 끔` 한 줄은 이렇게 읽는다.

- **상황**: 가짜 AWS에 db-1 서버가 없는 상태를 만들었다.
- **기대**: 스크립트가 web-1도 끄지 말고 멈춰야 한다.
- **PASS**: 실제로 그렇게 됐다. 아래 세 가지가 모두 기대와 같았다.
  1. 종료 코드 (성공 0 / 실패 1)
  2. 끝난 뒤 web-1·db-1 상태
  3. 로그에 기대한 문구가 있는지

FAIL이 하나라도 있으면 그 아래에 이유와 로그가 함께 나온다.

# ALB 가짜 시험 (test/alb-fake-test.sh)

`build-alb.sh`(3회차 ALB·HTTPS)가 예외 상황에서 멈춰야 할 때 멈추는지, **진짜 AWS·인터넷 없이** 확인한다.
ec2 시험과 같은 방식이고, 추가로 **가짜 curl**도 쓴다 (NET-01·01-b 확인 단계용).

## 실행

```bash
cd 이민성/infra
bash test/alb-fake-test.sh
```

마지막 줄이 `결과: PASS 59 / FAIL 0`이면 통과.

## 상황을 바꾸는 방법

가짜 aws는 임시 폴더(`$FK`)의 파일을 보고 대답을 바꾼다. 예: `alb_exists` 파일이 있으면 "ALB가 이미 있음", `cert_never`가 있으면 "인증서가 계속 검증 중", `crlf`가 있으면 Windows처럼 줄 끝에 `\r`을 붙인다.
PASS 판정은 ① 종료 코드 ② 로그 문구 ③ **ALB가 만들어졌는지 여부** 세 가지를 본다 (멈춰야 할 때 ALB가 생기면 FAIL).
가짜 aws는 **만든 것을 기억**한다(대상 그룹·ALB·리스너·A 레코드). 그래서 "중간에 실패 → 다시 실행"을 그대로 재현할 수 있다.
가짜 curl은 **Windows처럼 `/dev/null`을 받으면 오류(23)**를 낸다 (11/11 실제 실행에서 발견).
