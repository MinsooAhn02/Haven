# 구축 스크립트 설명

`이민성/infra/`의 스크립트가 어떤 역할을 나눠 맡는지 설명한다. 값의 근거는 [설계.md](../network/설계.md)와 [AWS 운영 결정](../../docs/AWS_운영결정.md)이다.

## 1. 파일별 역할

| 파일 | 하는 일 |
|---|---|
| `config.sh` | 리전·CIDR·서버 사양·태그·인스턴스 프로파일 이름·팀 계정 번호 같은 **값만** 모아 둔다 |
| `common.sh` | 여러 스크립트가 같이 쓰는 **기능**: 로그, DRY-RUN이면 명령만 출력, 태그, 자원 ID 기록, 빈 값이면 멈추기, 계정 확인(root 금지·팀 계정 대조) |
| `build.sh` | **처음 구축**: VPC → 서브넷 → IGW → 라우팅 → SG → S3 Endpoint → NAT(nat-up.sh 호출) → EC2 2대 |
| `nat-up.sh` | **아침**: EIP → NAT → 경로를 새 NAT로 → 경로 확인(RST-02) |
| `nat-down.sh` | **밤**: NAT 삭제 → EIP 해제 → 남은 것 없는지 확인(RST-03) |
| `destroy.sh` | **전체 삭제**: 기본은 목록만 출력. `--delete` + 확인 문구 입력 시에만 삭제 (실행 전 민수 확인) |
| `ec2-stop.sh` | EC2 중지 (web-1 → db-1 순) |
| `ec2-start.sh` | EC2 시작 (db-1 → web-1 순) + 공인 IP·SSM 확인 |
| `night.sh` | 21시: ec2-stop + nat-down (자세한 건 EC2시작중지설명.md) |
| `morning.sh` | 09시: nat-up + ec2-start (평일 09~21시만) |

## 2. 실행할 때의 연결

```
bash build.sh
  └ common.sh를 불러온다
       └ config.sh를 불러온다
```

- `build.sh`는 맨 위에서 `common.sh`를 불러오고, `common.sh`는 맨 위에서 `config.sh`를 불러온다.
- 그래서 `build.sh` 하나만 실행해도 세 파일이 모두 쓰인다.

## 3. 나눈 이유

- 앞으로 만들 `nat-up.sh`, `nat-down.sh`, `destroy.sh`도 같은 값(`config.sh`)과 같은 기능(`common.sh`)을 쓴다. 새 스크립트는 순서(레시피)만 새로 쓰면 된다.
- 값을 바꿀 때 `config.sh` 한 곳만 고치면 모든 스크립트에 반영된다. 파일마다 따로 적으면 한 곳만 고치고 다른 곳을 빠뜨리는 실수가 생긴다.
- 다른 계정에서 다시 만들 때(결정 9번)도 `config.sh` 값만 바꾸거나, 실행할 때 같은 이름의 환경변수로 덮어쓰면 된다.
  - 예: `AWS_REGION=us-east-1 bash build.sh`

## 4. 알아둘 점(한계)
- 공휴일은 못 막는다. morning은 요일만 보기 때문에 평일 공휴일에도 켜진다. 쉬는 날이면 morning을 안 돌리면 된다.
- SSM 확인이 틀릴 수 있다. 서버를 껐다가 바로 다시 켜면, SSM이 끄기 전의 “Online” 상태를 잠깐 그대로 보여 줄 수 있다. 그러면 확인이 실제보다 먼저 통과된다. 밤새 꺼 둔 경우는 괜찮다. 확실한 확인은 연결확인표 SSM-01이다.
