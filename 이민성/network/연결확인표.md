# SSM·Web→DB·필요 출구·직접 접근 거부 확인표

[설계.md](설계.md)의 네트워크·SG 설계가 실제로 동작하는지 확인하는 표다. 기대 결과는 설계와 [기본 명세](../../docs/구현명세/기본프로젝트_구현명세.md) NET-01~06에서 정했고, 실제 결과는 승인·구축 뒤 채운다.

- **상태**: 기대값 작성 중 (AWS 쓰기 작업은 승인 전 보류)
- **실행 환경**: (구축 후 기록: 리전, 계정 구분, 실행 위치)
- **대상**: (구축 후 기록: 인스턴스 ID·IP는 가려서 기록)
- **ID 규칙**: `NET-`은 명세 ID, `SSM-`·`OUT-`·`RST-`는 이 표의 자체 번호
- **시험용 출발지**: sg-web·sg-alb가 아닌 SG를 붙이고 **아웃바운드를 연** VPC 내부 출발지. 출발지 쪽 SG에서 막히지 않아야 목적지 SG를 시험할 수 있다

## A. SSM 접속

| ID | 출발지 → 목적지 | 방법 | 기대 결과 | 설계 근거 | 실제 | 증거 |
|---|---|---|---|---|---|---|
| SSM-01 | AWS → web-1, db-1 (등록 상태) | `aws ssm describe-instance-information` | web-1, db-1 모두 `PingStatus: Online` | 설계 5절 SSM 출구(NAT) | | |
| SSM-02 | 허가된 운영 주체 → web-1 | `aws ssm start-session --target <web-1 ID>` | 세션 **열림** | 명세 4.1 SSM 관리, IAM-07/08 | | |
| SSM-03 | 허가된 운영 주체 → db-1 | 같은 명령, db-1 | 세션 **열림** | 같음 | | |
| NET-05 | 일반 계정 → web-1 | 같은 명령, 일반 계정으로 | `AccessDeniedException`, 세션 **안 열림** | 명세 NET-05 | | |
| SSM-04 | 인터넷 → 모든 SG:22/3389 | `aws ec2 describe-security-groups` | 22·3389 인바운드 규칙 **없음** (SG CLI SG-01 위반 없음) | 설계 4.3, 명세 4.1 | | |

## B. Web → DB

| ID | 출발지 → 목적지 | 방법 | 기대 결과 | 설계 근거 | 실제 | 증거 |
|---|---|---|---|---|---|---|
| NET-03 | web-1 → db-1:5432 | web-1에 SSM 접속 → `psql -h <db-1 IP> -p 5432 -U <앱 계정>` | 접속 **성공**, 허용된 앱 계정으로 로그인 | 설계 4절 sg-db ← sg-web 5432 | | |
| NET-03-b | web-1 → db-1:5432 (허용 안 된 계정) | 같은 명령, 다른 계정 | TCP 연결은 되고 **인증 실패** (SG가 아니라 DB가 거절) | 명세 NET-03 "허용된 계정으로" | | |
| NET-04 | 시험용 출발지 → db-1:5432 | `timeout 5 bash -c '</dev/tcp/<db-1 IP>/5432'` | **timeout** (Connection refused면 SG 통과 → FAIL) | 설계 4절 sg-db는 sg-web만 허용 | | |
| NET-04-b | 시험용 출발지 → db-1:22 | 같은 명령, 포트 22 | **timeout** | 설계 4절 sg-db 인바운드는 5432만 | | |
| NET-04-c | ALB → db-1 | ALB는 명령 실행 불가 → `describe-security-groups`로 sg-db 규칙 확인 | sg-alb 출처 규칙 **없음** (SG CLI SG-04 위반 없음) | 설계 4.3 ALB→DB 거부 | | |

## C. 필요 출구

| ID | 출발지 → 목적지 | 방법 | 기대 결과 | 설계 근거 | 실제 | 증거 |
|---|---|---|---|---|---|---|
| OUT-01 | web-1 → DNS | `getent hosts ssm.ap-northeast-2.amazonaws.com` | IP 주소 **반환** | 설계 4절 Amazon DNS는 SG로 막히지 않음 | | |
| OUT-02 | web-1 → SSM 엔드포인트:443 | `curl -sS -o /dev/null -w '%{http_code}' https://ssm.ap-northeast-2.amazonaws.com` | HTTP 응답 코드 **받음** (코드는 무관, timeout 아님) | 설계 5절 NAT 경유 443 | | |
| OUT-03 | web-1 → Ubuntu apt 저장소:80 | `sudo apt update` | 저장소 목록 **받아옴**, 오류 없음 | 설계 4.2 sg-web 80, AWS_운영결정 5번 | | |
| OUT-04 | db-1 → Ubuntu apt 저장소:80 | 같음 | **받아옴** | 설계 4.2 sg-db 80 | | |
| OUT-05 | private 서브넷 → S3 | `aws ec2 describe-route-tables`로 rt-private 확인 | S3 prefix list(`pl-`) → `vpce-` 경로 **있음** | 설계 3절 S3 Gateway Endpoint | | |
| OUT-06 | web-1 → 메일 | 메일 방식 확정 후 기입 | (SES API면 443 성공 / SMTP면 587 규칙 추가 후 성공) | 결정 대기 | | |
| OUT-07 | db-1 → 인터넷:8080 (허용 안 한 포트) | `timeout 5 bash -c '</dev/tcp/<외부 IP>/8080'` | **timeout** | 설계 4.2 sg-db outbound는 80·443만 | | |
| OUT-08 | web-1 → 임의 외부 사이트:443 | `curl -sS -o /dev/null -w '%{http_code}' https://example.com` | **성공** — 막는 규칙이 없음. PASS가 아니라 **남은 위험**으로 기록 | 설계 4절 443 잔여 위험 | | |
| OUT-09 | web-1 → pypi.org:443 | `curl -sS -o /dev/null -w '%{http_code}' https://pypi.org/simple/` | `200` **받음** | 설계 5.1 Python 패키지 | | |
| OUT-10 | web-1, db-1 → CloudWatch Logs | 로그 설정 후 `aws logs describe-log-streams`로 확인 | 로그 **도착** | 설계 5.1 로그/AWS API (권한 김보람) | | |
| OUT-11 | db-1 → S3 백업 버킷 (Gateway) | 지정 prefix에 시험 파일 업로드, 다른 prefix에도 시도 | 지정 prefix **성공**, 다른 버킷·prefix는 **AccessDenied** | 설계 5.1 S3 백업, Endpoint 정책 (김보람) | | |
| OUT-12 | web-1, db-1 apt 저장소 주소 | `grep URIs /etc/apt/sources.list.d/ubuntu.sources` | `http://` 주소 (80 포트 사용 확인) | AWS_운영결정 5번 | | |

## D. 직접 접근 거부

| ID | 출발지 → 목적지 | 방법 | 기대 결과 | 설계 근거 | 실제 | 증거 |
|---|---|---|---|---|---|---|
| NET-01 | 인터넷 → 도메인(ALB):443 | `curl -I https://<도메인>` | 정상 응답, 인증서 **유효** | 명세 NET-01, 설계 4절 sg-alb 443 | | |
| NET-01-b | 인터넷 → ALB:80 | `curl -I http://<도메인>` | `301` 응답, `Location: https://...`로 **전환** | 설계 4절 sg-alb 80 = HTTPS redirect 전용 | | |
| NET-02-a | web-1, db-1 공인 IP | `aws ec2 describe-instances` (PublicIpAddress) | 값 **없음** | 설계 2절 공인 IP 자동 할당 끔 | | |
| NET-02-b | private 라우팅 | `aws ec2 describe-route-tables` (rt-private) | `0.0.0.0/0 → nat-`, `igw-` 경로 **없음** | 설계 3절 | | |
| NET-02-c | sg-web 인바운드 | `aws ec2 describe-security-groups` | 80 ← sg-alb **만**, `0.0.0.0/0` 없음 (SG CLI SG-03 위반 없음) | 설계 4절 | | |
| NET-02-d | 시험용 출발지 → web-1:80 | `timeout 5 bash -c '</dev/tcp/<web-1 IP>/80'` | **timeout** (ALB 우회 불가) | 설계 4절 sg-web은 sg-alb만 허용 | | |

## E. 재시작·장애 상황

| ID | 상황 | 방법 | 기대 결과 | 설계 근거 | 실제 | 증거 |
|---|---|---|---|---|---|---|
| NET-06 | web-1 재부팅 후 | 재부팅 → SSM-01·SSM-02·OUT-03 다시 실행 | SSM **Online 복구**, 세션·업데이트 **성공** | 명세 NET-06 | | |
| NET-06-b | db-1 재부팅 후 | 재부팅 → SSM-03·OUT-04·NET-03 다시 실행 | SSM **복구**, Web→DB **재접속 성공** | 명세 NET-06 | | |
| RST-01 | NAT Gateway가 없을 때 (비용 때문에 삭제한 기간) | 삭제 기간에 SSM-01·OUT-03·OUT-05 확인 | SSM **Offline**·업데이트 **실패**, S3 경로는 **유지** | 설계 5.2 NAT 삭제·blackhole | | |

RST-01은 시험하려고 NAT를 일부러 지우지 않는다. 비용 계획대로 삭제한 기간에 확인되는 대로 기록한다.
